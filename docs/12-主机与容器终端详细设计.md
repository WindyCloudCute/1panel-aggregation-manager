## 1. 目标与非目标

### 1.1 目标

1. 浏览器内提供 **主机终端**（1Panel 本机 shell）与 **容器 exec 终端**（`docker exec -it`）；
2. 链路：`浏览器 ⇄ PanelFleet /ws/terminal ⇄ 1Panel WebSocket`，服务端桥接、双向转发；
3. 仅 **Admin**（cookie 会话 + `Admin` policy）可用；Origin 校验；会话空闲/最长时长限制；输入帧大小与频率限制；
4. 审计：`terminal.session.start` / `terminal.session.end`（节点、模式、容器、操作者、时长、重连次数、输入帧数、输出字节数），**不记录任何输入内容**；
5. 本地打包 xterm.js（不引 CDN），网络不可用时退化到零依赖「简易终端」；
6. `Terminal:Enabled` 可整体关闭（默认开启）；
7. 反向代理（Nginx/IIS）Upgrade 透传的部署说明。

### 1.2 非目标

- 不实现 SSH 凭据/主机清单管理（沿用 1Panel 既有的「本机 SSH 连接」与主机 SSH 配置）；
- 不实现 1Panel 的终端会话列表/踢出 UI（`hosts/terminal/sessions/*` 保留为 1Panel 自身能力）；
- 不做按键录制、命令审计、命令白名单（明确不记录输入内容；命令级管控属于后续阶段）；
- 不实现文件传输、AI 命令生成（1Panel 的 `@ai` 能力不暴露给 PanelFleet）。

## 2. 真实 1Panel v2.3.2 终端契约（探测结论）

> 探测环境：真实节点 `http://<node>:1000`（Debian 13 / 1Panel v2.3.2，core+agent 架构）。
> 原则：只发 GET/POST 只读请求；WS 只执行 `echo` / `uptime` 后立即关闭；未执行任何破坏性命令。
> 本节不含 API Key、节点地址等敏感信息。

### 2.1 版本与架构

1Panel v2.3.x 采用 **core（面板，监听对外端口）+ agent（本机 unix socket）** 架构：浏览器/外部客户端访问 core 的 `/api/v2/...`，core 校验鉴权后把请求反向代理到 agent；终端 WS 也走同一路径（core 以 `net/http/httputil.ReverseProxy` 代理，承载 WebSocket）。

### 2.2 接口清单（已实测）

| 用途 | 方法 + 路径 | 说明 |
|---|---|---|
| 主机终端（本机 shell） | `GET /api/v2/hosts/terminal/local` | 通过「本机 SSH 连接」（`LocalSSHConn`）打开；query：`cols`、`rows`、可选 `command`（初始命令）、`session`（重连）、`terminalPersistent` |
| 主机 SSH 终端 | `GET /api/v2/hosts/terminal/ssh` | query：`id`（1Panel 主机记录 id）、`cols`、`rows`、`command`、`title`、`session`、`terminalPersistent` |
| 容器 exec | `GET /api/v2/hosts/terminal/container` | query：`source=container`、`containerid`（容器名或 ID）、`user`（可选）、`command`（必填，单可执行文件，如 `/bin/sh`）、`cols`、`rows`、`session` |
| 会话列表 | `POST /api/v2/hosts/terminal/sessions/search` | 返回当前 API Key/用户可见的会话数组（本探测回 `data:null`，即无会话） |
| 关闭会话 | `POST /api/v2/hosts/terminal/sessions/close` / `closeAll` | 请求体 `{id}` / 空 |
| 本机 SSH 连接配置 | `GET /api/v2/settings/ssh/conn` | 返回 `{addr,port,user,authMode,localSSHConnShow,...}`；**含私钥字段，禁止记录/展示** |
| 容器列表（容器名校验用） | `POST /api/v2/containers/search` | 请求体 `{page,pageSize,state:"all",orderBy:"name",order:"ascending"}`；响应项含 `containerID/name/state/imageName` |
| 终端能力（内部） | `GET /api/v2/internal/terminal/capabilities` | core 仅允许本地 agent 调用，外部请求 403 |

补充事实：

- 终端**没有全局启用开关**。主机终端能否打开取决于 1Panel 是否配置了「本机 SSH 连接」；容器终端取决于 Docker 与容器是否存在且在运行；
- WS 路由对普通 GET（未带 `Upgrade`）返回 `{"code":200,"message":"success","data":null}`，可用于轻量探测路由存在性与鉴权；
- 容器 `command` 会作为 `docker exec -it <containerid> <command>` 的**单个参数**传入，因此只能是可执行文件路径（`/bin/sh`），不能带参数；
- 容器 `containerid` 同时接受完整容器 ID 与容器名。

### 2.3 WS 握手鉴权（重要）

WS 升级请求复用 1Panel 的 API Key 签名头，**不需要 ticket、不需要 cookie**：

```
1Panel-Token: HMAC-SHA256(key=apiKey, msg="1panel:"+timestamp) 小写 hex（现代密钥）
             或 MD5("1panel"+apiKey+timestamp) 小写 hex（legacy 密钥）
1Panel-Timestamp: unix 秒
可选 1Panel-Signature-Version: hmac-sha256 | md5（不传时服务端两种都尝试）
```

实测结论：

1. **不需要**先把 API Key 换成 ticket；把签名头直接放在 WS 升级请求里即可（`ClientWebSocket.Options.SetRequestHeader`）；
2. **本节点的 API Key 只接受 legacy MD5 签名**，HMAC 签名被拒：HTTP **200** + body `{"code":401,"message":"API 接口密钥错误","data":null}`，`ClientWebSocket.ConnectAsync` 抛 `WebSocketException`（"服务器返回了状态代码 200，而状态代码应为 101"）；MD5 签名则 101 升级成功。
   - 因此终端后端必须实现 **Auto 策略**：先 HMAC，握手失败回退 MD5，并按节点缓存结果（见 §5.4）；
3. 携带 API Key 的终端受「授权租约」约束：core 给 agent 透传 `X-Panel-User-ID` / `X-Panel-Auth-Session-ID`（API Key 场景为 `api-key:<keyId>` 或 legacy 用户）与 `X-Panel-Auth-Lease-Until`（约 90 秒）；agent 到期关闭会话，需通过重连续租（与 §2.5 的 60 秒重校验同机制）；
4. 若把 API Key 面板接口配置为「接口状态=关闭」或 IP 白名单不含 PanelFleet 主机，WS 与 REST 一样被拒（HTTP 200 + 业务 code 401）；
5. 节点 TLS 自签场景需放宽证书校验（逐节点 `TlsPolicy.AllowSelfSigned`，与 REST 客户端一致）。

> **实现坑（务必记录）**：1Panel 鉴权失败不是 HTTP 401，而是 HTTP 200 + JSON `code=401`；`ClientWebSocket` 只表现为「状态码 200 ≠ 101」的 `WebSocketException`，且不会返回 body。桥接层必须把这类握手失败识别为「鉴权失败候选」并回退另一种签名方式，不能直接当网络错误。

### 2.4 消息帧协议（文本 JSON）

服务端 → 客户端：

| type | 字段 | 说明 |
|---|---|---|
| `session` | `id` | attach/重连成功后的第一条消息，携带会话 id |
| `cmd` | `data`（base64） | 终端输出字节（含 ANSI 转义），约每 60ms 合并一批 |
| `heartbeat` | `timestamp` | 回显客户端心跳（用于延迟测量） |
| `ai_notice` | `level`/`message` | 1Panel AI 功能提示（PanelFleet 不启用，忽略） |

客户端 → 服务端：

| type | 字段 | 说明 |
|---|---|---|
| `cmd` | `data`（base64）、可选 `line` | 键盘输入字节；`line` 仅 1Panel AI 使用，PanelFleet 不发送 |
| `resize` | `cols`、`rows` | 终端窗口尺寸 |
| `heartbeat` | `timestamp` | 心跳，服务端原样回显 |

保活：

- 1Panel 服务端每 **30s** 发协议级 Ping，**75s** 内无消息/无 pong 断开；客户端每 30s 发 JSON heartbeat 亦可续期（实测有效）；
- 客户端（PanelFleet 桥）每 20–30s 发送 JSON heartbeat，并依赖 .NET `ClientWebSocket` 自动回复 pong。

### 2.5 关闭码与 60 秒重校验（已实测）

| 关闭码 | 含义 | PanelFleet 处理 |
|---|---|---|
| `1000` | 正常结束（客户端主动关闭 / shell 退出） | 正常结束会话 |
| `4404` | 会话不存在（重连时 session 已过期） | 提示会话已结束，可重新连接 |
| `4409` | 会话已在其它连接 attach | 提示会话被接管 |
| `4410` | **需要授权重校验**（服务端每 60s 主动触发） | 桥内部带 `session=<id>&terminalRevalidate=1` 重连续租（30s 宽限） |
| `1011` | 服务端内部错误 | 提示上游错误 |

实测：连接后 **第 60 秒**收到 `4410`（reason=`terminal authorization revalidation required`）；在 30 秒内带 `session` + `terminalRevalidate=1` 重连后，第一条帧仍为同一 `session.id`，输出从 ring buffer 游标续传、不重复、不丢屏。

### 2.6 `terminalPersistent`

- `terminalPersistent=true`：异常断线后会话保留 **30 分钟**（graceTimeout），期间可重连；
- 不传/`false`：**异常断线立即销毁会话**；客户端主动发 `1000` 则立即销毁。

PanelFleet **不启用** persistent：浏览器断开时桥主动向上游发 `1000`，避免审计结束（session.end）后仍残留可被他人 attach 的 shell。浏览器网络闪断由浏览器侧「重连」按钮重新建立**新**会话。

### 2.7 错误路径

- 上游在升级后才发现错误（如本机 SSH 未配置、容器不存在）时，agent 先尝试用 Close 控制帧携带错误文本，失败则改发一条 `{"type":"cmd","data":"<base64 错误文本>"}`。因此桥接层必须把「连接后立即出现的 cmd 帧内容」也作为可能的错误提示来源（同时仍转发给浏览器）。
- 本机 SSH 未配置时 1Panel 返回 `no such ssh conn info in db`；PanelFleet 在打开主机终端前用 `GET /api/v2/settings/ssh/conn` 预检，直接给出中文可读错误「节点未配置本机 SSH 连接」。

## 3. 总体架构

```
┌─────────────┐  WebSocket(JSON, cookie)   ┌──────────────────────────┐   1Panel WS(JSON, API Key 头)   ┌──────────────┐
│ 浏览器 xterm │ ─────────────────────────▶ │ PanelFleet /ws/terminal  │ ─────────────────────────────▶ │ 1Panel core  │
│ (本地 xterm) │ ◀───────────────────────── │  TerminalBridge(会话桥)  │ ◀───────────────────────────── │ → agent shell│
└─────────────┘        output(ready/closed)└──────────────────────────┘      session/cmd/resize/…     └──────────────┘
                                             │ TerminalSessionManager（校验/审计）
                                             │ ITerminalBackend（真实实现：ClientWebSocket）
                                             └─ INodeStore / INodeSecretProtector / IPanelClientFactory / IAuditStore
```

要点：

1. **浏览器只与 PanelFleet 通信**，永不直连 1Panel；API Key 只在服务端内存中短暂使用（与 REST 一致），不进入浏览器；
2. 浏览器协议是 PanelFleet 自定义的简化协议（§4），1Panel 的 `session/ai_notice/heartbeat` 等细节不外泄；
3. 桥在服务端完成 1Panel 的 60s 重校验续租，**浏览器完全无感**；
4. 每个浏览器连接对应一个 1Panel 会话；浏览器断开即关闭上游会话（不发 persistent）。

## 4. 浏览器 ⇄ PanelFleet 协议

传输：文本 WebSocket 帧（JSON UTF-8）。二进制/终端字节一律 base64，避免编码损坏。

### 4.1 客户端 → 服务端

| type | 字段 | 约束 |
|---|---|---|
| `input` | `data`（base64） | 单帧解码后 ≤ `Terminal:MaxFrameBytes`（默认 65536）；频率见 `MaxInputFramesPerSecond`（默认 30 帧/秒）与 `MaxInputBytesPerSecond`（默认 128 KiB/s） |
| `resize` | `cols`、`rows` | 限定 20..500 / 5..200 |
| `ping` | `timestamp` | 服务端回 `{"type":"pong","timestamp":...}`；纯前端延迟测量，不影响上游 |

### 4.2 服务端 → 客户端

| type | 字段 | 说明 |
|---|---|---|
| `ready` | `sessionId`、`mode`(`host`/`container`)、`nodeId`、`nodeName`、`container`、`cols`、`rows` | 上游连接成功后第一条；Page 显示连接状态 |
| `output` | `data`（base64） | 终端输出原始字节（ANSI 原样） |
| `pong` | `timestamp` | 心跳应答 |
| `error` | `code`、`message` | 可读错误（中文）；`code` 见 §6.4 |
| `closed` | `reason`、`message`、`canReconnect` | 会话结束；`reason` ∈ `user`/`idle`/`max_duration`/`upstream_closed`/`upstream_error`/`revalidate_failed`/`input_limit`/`server` |

### 4.3 WS 关闭码

| 码 | 含义 |
|---|---|
| `1000` | 正常结束（用户关闭、idle、最长时长、上游正常退出） |
| `1011` | 服务端/上游错误 |
| `4401` | （升级前）鉴权失败由 HTTP 401 表达，不使用该码 |

## 5. Application 层设计

### 5.1 配置 `TerminalOptions`（绑定 `Terminal` 节）

```csharp
public sealed class TerminalOptions
{
    public bool Enabled { get; set; } = true;                     // 总开关（默认开启）
    public int IdleTimeoutSeconds { get; set; } = 1800;           // 空闲断开：默认 30 分钟无输入
    public int MaxSessionMinutes { get; set; } = 240;             // 单会话最长 4 小时
    public int MaxFrameBytes { get; set; } = 65536;               // 单个浏览器输入/输出帧上限
    public int MaxInputFramesPerSecond { get; set; } = 30;        // 输入帧频率上限（令牌桶）
    public int MaxInputBytesPerSecond { get; set; } = 131072;     // 输入字节速率上限
    public int MaxConcurrentSessions { get; set; } = 20;          // 进程内活跃会话上限
    public string[] AllowedOrigins { get; set; } = [];            // 额外允许的 Origin（同源始终允许）
    public bool AllowMissingOrigin { get; set; } = true;          // 非浏览器客户端（无 Origin）放行
    public void Validate();
}
```

启动校验：`Enabled=false` 时其余仅做宽松校验；数值范围：`IdleTimeoutSeconds` 30..86400、`MaxSessionMinutes` 1..1440、`MaxFrameBytes` 1024..1048576、`MaxInputFramesPerSecond` 5..1000、`MaxInputBytesPerSecond` 1024..10485760、`MaxConcurrentSessions` 1..200。

### 5.2 模型与状态机

```csharp
public enum TerminalMode { Host = 0, Container = 1 }
public enum TerminalSessionState { Connecting, Active, Revalidating, Closed, Failed }

public sealed record TerminalSessionRequest(
    NodeId NodeId, TerminalMode Mode, string? Container, string? ContainerCommand, string? ContainerUser, int Cols, int Rows);

public sealed record TerminalSessionInfo(
    string SessionId, NodeId NodeId, string NodeName, TerminalMode Mode, string? Container,
    DateTimeOffset StartedAt, TerminalSessionState State, int Cols, int Rows);
```

会话生命周期：

```
OpenAsync 校验 ──失败──▶ TerminalException（HTTP 4xx/关闭前错误帧）
   │成功
   ├─ registry 注册（容量上限） + 审计 terminal.session.start
   └─ RunAsync：连接上游 ──失败──▶ 错误帧 + 审计 end(reason=upstream_error)
        │成功
        └─ ready ─▶ 双泵运行 ──(4410)──▶ 内部重连续租（≤3 次，500ms/1s/2s 退避）
             │
             ├─ 浏览器关闭/断网 → 上游 1000 → 审计 end(reason=user)
             ├─ 空闲超时        → 审计 end(reason=idle)
             ├─ 最长时长        → 审计 end(reason=max_duration)
             └─ 上游关闭/错误   → 审计 end(对应 reason) + 浏览器 closed(canReconnect)
```

### 5.3 `ITerminalBackend` 抽象

```csharp
public sealed record TerminalConnectContext(
    NodeDescriptor Node, TerminalMode Mode, string? Container, string? ContainerCommand, string? ContainerUser, int Cols, int Rows);

public interface ITerminalBackend
{
    Task<ITerminalConnection> ConnectAsync(TerminalConnectContext context, string? sessionId, bool revalidate, CancellationToken ct);
}

public interface ITerminalConnection : IAsyncDisposable
{
    string? SessionId { get; }
    Task<TerminalServerFrame> ReceiveAsync(CancellationToken ct);
    Task SendInputAsync(byte[] data, CancellationToken ct);
    Task SendResizeAsync(int cols, int rows, CancellationToken ct);
    Task CloseAsync(CancellationToken ct);   // 发送 1000 并等待关闭
}
```

真实实现 `PanelTerminalBackend`：

1. URL：`ws(s)://<BaseUri host+path>/api/v2/hosts/terminal/local|container`（http→ws、https→wss；BaseUri 带反代子路径时按 `PanelEndpoint.Combine` 规则拼接）；query 顺序固定：`cols,rows[,source,containerid,user,command]`，重连追加 `session`、`terminalRevalidate=1`；
2. 鉴权头：`1Panel-Token`、`1Panel-Timestamp`（`TimeProvider.GetUtcNow()` + 节点 `ClockOffsetSeconds`），token 计算见 §5.4；
3. TLS：`TlsPolicy.Strict` 默认严格；`AllowSelfSigned` 时 `Options.RemoteCertificateValidationCallback = (_,_,_,_) => true`；
4. 连接成功后读取第一条消息（`session`）拿会话 id；`Transport` 异常映射为 `TerminalUpstreamException`（可读中文，不含密钥）；
5. `ReceiveAsync` 会合并分片帧，解析为 `TerminalServerFrame`（`Output`/`Session`/`Heartbeat`/`AiNotice`/`Closed`/`Unknown`）。

### 5.4 签名与 Auto 回退（`TerminalSignature` + `TerminalAuthCache`）

```csharp
internal static class TerminalSignature
{
    public static string Compute(string apiKey, long unixSeconds, AuthMode mode); // HmacSha256 / Md5
}

public sealed class TerminalAuthCache   // singleton，并发字典
{
    public AuthMode? TryGet(NodeId nodeId);
    public void Remember(NodeId nodeId, AuthMode mode);
    public void Forget(NodeId nodeId);
}
```

连接策略：

1. 节点 `AuthMode` 显式为 `HmacSha256`/`Md5` → 只尝试该方式（尊重用户配置，连续失败提示用户检查密钥类型）；
2. `AuthMode.Auto`：先查缓存；无缓存先 HMAC，握手失败（`WebSocketException` 且是「非 101」/HTTP 200）再 MD5；
3. 成功后写缓存（避免每次连接双握手）；密钥被更新/测试失败时清缓存（NodeService 更新节点后由后续连接自然刷新，失效缓存也可由 `Forget` 显式清除）；
4. 所有候选都失败 → `TerminalUpstreamException(code=upstream_auth_failed, "1Panel 鉴权失败，请检查 API Key、接口状态与 IP 白名单")`。

### 5.5 预检（`TerminalSessionManager.OpenAsync`）

| 检查 | 实现 | 失败提示 |
|---|---|---|
| 总开关 | `TerminalOptions.Enabled` | 终端功能已禁用（端点 403） |
| 节点存在且启用 | `INodeStore.FindAsync` + `IsEnabled` | 「节点不存在或已禁用」 |
| 主机模式：本机 SSH 已配置 | `GET api/v2/settings/ssh/conn`（成功且 `addr` 非空） | 「节点未配置本机 SSH 连接（可在 1Panel 设置 → SSH 连接中配置）」 |
| 容器模式：容器存在且运行 | `POST api/v2/containers/search`（`state=all`，匹配 name/containerID） | 「容器不存在或不属于该节点」/「容器未运行，无法打开终端」 |
| 容量 | `TerminalSessionRegistry` | 「当前终端会话数已达上限」 |
| 参数格式 | 命令/用户/容器名白名单正则（`^[A-Za-z0-9_./-]+$` 等） | 「容器命令/用户/名称包含非法字符」 |

预检使用 `IPanelClientFactory`（与 REST 相同的客户端），节点解密仅在内存中进行；`settings/ssh/conn` 响应包含私钥字段，**只做存在性判断，不记录、不缓存、不回传**。

### 5.6 桥（`TerminalBridge`）

- 双泵：`PumpUpstreamAsync`（转发输出、处理 4410/关闭）与 `PumpBrowserAsync`（输入/尺寸/心跳、帧上限与令牌桶限流）；外加 1s 粒度的 `MonitorAsync`（空闲/最长时长，`TimeProvider` 注入便于单测）；
- 4410 续租：关闭当前上游连接，用 `sessionId + terminalRevalidate=1` 重连（≤3 次；500ms/1s/2s 退避，总预算 ≤25s）；重连期间浏览器输入进入有界缓冲（默认 128 KiB，超限关闭）；成功后 `revalidateCount++`，浏览器**不感知**；
- 浏览器断开：取消双泵 → 上游 `CloseAsync()`（1000）→ 结束；
- 任一泵结束/超时/限流触发 → 统一 `TerminalCloseOutcome(reason,message,canReconnect)`，由会话句柄写审计、由桥发 `closed` 帧（若浏览器连接仍可用）并以 1000/1011 关闭浏览器 WS；
- 输出字节计入 `OutputBytes`（审计用），输入只计帧数与字节数，**不保存内容**；日志一律不记录终端内容。

### 5.7 审计

| Action | TargetType | TargetId | NodeId | DetailJson |
|---|---|---|---|---|
| `terminal.session.start` | `node` | 节点 id | 节点 id | `{sessionId, mode, nodeName, container?, command?, user?, cols, rows}` |
| `terminal.session.end` | `node` | 节点 id | 节点 id | `{sessionId, mode, nodeName, container?, durationSeconds, revalidateCount, inputFrames, inputBytes, outputBytes, closeReason, error?}` |

- 审计走 `IAuditStore`（与既有模块一致）；审计失败只记日志，不影响会话；
- **绝不写入输入内容、输出内容、API Key、SSH 私钥**；
- 会话开始/结束各一条；中途 4410 重连不产生额外审计。

### 6.2 鉴权、Origin 与 CSRF 论证

- **鉴权**：cookie 会话（`PanelFleet.Auth`）+ `Admin` policy。WS 升级请求由 ASP.NET Core 认证/授权中间件先处理：未登录 → 401，已登录非 Admin → 403（均为升级前的 HTTP 响应）。
- **CSRF**：普通跨站表单无法发起带 `Upgrade: websocket` 的请求；但浏览器 WebSocket **不受同源策略限制**，恶意页面可用受害者 cookie 发起跨站 WS（WebSocket hijacking）。因此对 WS 使用 **Origin 校验**而不是 antiforgery token：
  - 请求带 `Origin` 时，`Origin` 的 host+port 必须等于请求 `Host`（同源），或在 `Terminal:AllowedOrigins` 白名单中；`Origin: null` 拒绝；
  - 请求不带 `Origin` 时（非浏览器客户端，如集成测试/命令行）：`AllowMissingOrigin=true` 时放行（仍需 Admin cookie/测试认证），否则拒绝；
  - 反代场景要求代理透传原始 `Host` 与 `Origin`（见 §9）；`PanelFleet:ForwardedHeaders:Enabled=true` 时使用转发后的 Host。
- **禁止 GET 携带会话票据**：不使用 URL token/ticket，避免日志泄漏与历史记录泄漏；凭据只有 HttpOnly cookie。
- 页面 `/terminal` 使用 `[Authorize]`；非 Admin 用户访问页面时由现有 `RedirectToLogin`/授权流程处理（页面内再校验 Admin 并提示）。

## 9. 部署注意事项（反向代理 / WebSocket）

1. PanelFleet 自身监听（默认 `http://127.0.0.1:5188`）需要经 IIS/Nginx 暴露时，必须允许 WebSocket Upgrade：
   - **Nginx**：
     ```nginx
     location / {
         proxy_pass http://127.0.0.1:5188;
         proxy_http_version 1.1;
         proxy_set_header Upgrade $http_upgrade;
         proxy_set_header Connection $connection_upgrade;   # map $http_upgrade $connection_upgrade { default upgrade; '' close; }
         proxy_set_header Host $host;
         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
         proxy_set_header X-Forwarded-Proto $scheme;
         proxy_read_timeout 3600s;   # > 65s：1Panel 每 60s 重校验、每 30s 心跳
         proxy_send_timeout 3600s;
     }
     ```
   - **IIS**：安装 WebSocket Protocol 功能；`web.config` 反代场景使用 ARR + URL Rewrite，保留 `Upgrade` 头（`serverVariables` 允许 `HTTP_UPGRADE`）；
   - 反代后需设置 `PanelFleet:ForwardedHeaders:Enabled=true`，否则 Origin 与 Host 校验会因内外 Host 不一致而拒绝；
   - 若使用自定义域名，把该 Origin 加入 `Terminal:AllowedOrigins`（同源时不需要）。
2. 会话空闲 30 分钟、最长 240 分钟（可配）；反代空闲超时不要短于 65 秒，否则 WS 被代理层提前断开；
3. 仅 Admin 可用；如需对公网开放终端，必须在反代层再加一层访问控制（VPN/白名单），并确认 `PanelFleet:Listen:Url` 不直接暴露无 TLS 端口；
4. 终端会让浏览器直接持有长期 shell 能力：请确认审计表可查、日志级别不打印终端内容、API Key 权限按最小化原则配置。

## 12. 风险与遗留

| 风险 | 影响 | 对策 |
|---|---|---|
| 1Panel v2.3.x 之外版本终端路由/帧格式不同 | 连接失败 | 路由/帧集中在本模块，失败时中文提示；后续版本按 §2 重新探测 |
| API Key 类型（HMAC/legacy MD5）不一致 | 鉴权失败 | Auto 双策略 + 节点缓存 + 错误提示；用户可显式配置鉴权方式 |
| 用户误以为「终端 = 有权限」 | 越权风险 | Admin policy + Origin 校验 + 审计 + `Terminal:Enabled` 总开关 |
| 浏览器/反代空闲超时切断 | 终端断开 | 桥 30s 心跳 + 前端明确断线提示与重连按钮 + 反代 read timeout 说明 |
| 1Panel 每 60s 强制重校验 | 若桥实现错误会 60s 断线 | 已实现透明续租并单测覆盖；失败提示 `revalidate_failed` |
