## 1. 目标与非目标

### 1.1 目标

1. 计划任务**列表**（跨节点聚合、节点/分组/状态/关键字过滤、分页）；
2. **详情/编辑**：读取 1Panel `cronjobs/load/info`，按类型展示与编辑字段（周期、脚本、保留份数、超时、重试、忽略错误等）；
3. **写操作**（全部走 P5 内核：预览 → 确认 → 执行 → 审计）：创建、编辑、删除、启用/停用、立即执行；单节点 + 批量（批量风险 Critical、内核顺序执行、失败停止）；
4. **执行记录**（只读）：记录列表（时间范围/状态过滤、分页）+ 记录日志（`cronjobs/records/log`）；
5. 分组过滤（1Panel 自定义分组 `groups/search`，type=cronjob；该类型无分组时降级为「全部/未分组」）；
6. 周期助手：结构化周期（每月/每周/每天/每小时/N 天/N 小时/N 分钟/N 秒）↔ cron 表达式，并调用 1Panel `cronjobs/next` 展示接下来 5 次执行时间。

### 1.2 非目标

- 脚本库（`core/script/*`）管理、任务导入/导出、记录清理（`records/clean`）、运行中任务的强制停止（`cronjobs/stop`）——本轮不做（保留入口说明）；
- 任务告警配置（`alertCount/alertTitle/alertMethod`）——保留字段透传，不在 UI 暴露；
- 不实现 1Panel 内部类型的全部参数（如 snapshot 快照规则、cutWebsiteLog 日志切割、cleanLog 清理策略）——编辑时通过「字段透传」保留原值，创建仅开放 6 个常用类型（shell/curl/directory/app/website/database）。

## 2. 真实 1Panel v2.3.2 契约（探测结论）

> 探测环境：真实节点（1Panel v2.3.2），该节点计划任务数为 0。探测仅调用只读接口（search/groups/records/script/options/next/load info），**未在真实节点创建或执行任何任务**。本节不含 API Key、节点地址。

### 2.1 路由（源码核对 + 实测）

| 用途 | 方法 + 路径 | 请求 / 响应 |
|---|---|---|
| 列表 | `POST /api/v2/cronjobs/search` | `{page,pageSize,info,groupIDs,orderBy,order}`；`orderBy` 必填（name/status/createdAt），`order` 必填（null/ascending/descending）；响应 `{total,items}`（空为 `items:null`）— **实测 200** |
| 详情 | `POST /api/v2/cronjobs/load/info` | `{id}` → `CronjobOperate`；不存在时 HTTP 200 + `code=500, message="服务错误: record not found"` — **实测** |
| 创建 | `POST /api/v2/cronjobs` | `CronjobOperate`（name/type/spec 必填；retainCopies≥1、retryTimes≥0、timeout≥1） |
| 更新 | `POST /api/v2/cronjobs/update` | `CronjobOperate`（含 id；服务端保留原 type，必要时重建 cron entry） |
| 删除 | `POST /api/v2/cronjobs/del` | `{ids:[...], cleanData, cleanRemoteData}`（可批量；不可回滚） |
| 启用/停用 | `POST /api/v2/cronjobs/status` | `{id, status}`，status=`Enable`/`Disable` |
| 立即执行 | `POST /api/v2/cronjobs/handle` | `{id}`（任务正在执行时返回 `InExecuting` 业务错误） |
| 周期下次时间 | `POST /api/v2/cronjobs/next` | `{spec}` → 5 个 `yyyy-MM-dd HH:mm:ss` — **实测** |
| 执行记录 | `POST /api/v2/cronjobs/search/records` | `{page,pageSize,cronjobID,startTime,endTime,status}`（时间为 RFC3339；status=Success/Waiting/Unexecuted/Failed）— **实测** |
| 记录日志 | `POST /api/v2/cronjobs/records/log` | `{id}`（记录 id）→ `data` 为日志文本；文件不存在返回空串 |
| 脚本库下拉 | `GET /api/v2/cronjobs/script/options` | `[{id,name}]` — **实测非空**（本轮不用于创建表单） |
| 分组 | `POST /api/v2/groups/search` | 返回所有类型分组 `{id,name,type,isDefault}`；过滤 `type=cronjob`。**实测该节点只有 host/website 默认分组，无 cronjob 分组** → UI 必须容忍空分组 |

### 2.2 任务类型（前端 helper.ts 核对）

`shell`（Shell 脚本）、`app`（备份应用）、`website`（备份网站）、`database`（备份数据库）、`directory`（备份目录）、`log`（系统日志）、`curl`（URL 访问）、`cutWebsiteLog`、`clean`（磁盘清理）、`snapshot`、`ntp`、`syncIpGroup`、`cleanLog`。
**本轮创建表单开放 6 类**：shell / curl / directory / app / website / database；其余类型可列表/启停/立即执行/删除，编辑时保留原始字段（透传）。

### 2.3 周期 spec

- 生成规则（与前端 helper 一致）：
  - `perMonth` → `{minute} {hour} {day} * *`
  - `perWeek` → `{minute} {hour} * * {week}`
  - `perDay` → `{minute} {hour} * * *`
  - `perHour` → `{minute} * * * *`
  - `perNDay` → `{minute} {hour} */{day} * *`
  - `perNHour` → `{minute} */{hour} * * *`
  - `perNMinute` → `@every {minute}m`
  - `perNSecond` → `@every {second}s`
- 服务端支持多 spec（`spec` 以 `&&` 分隔）；本轮只生成单 spec，读取时按原样展示。
- 实测定时预览：`{"spec":"30 2 * * *"}` → `["2026-11-17 02:30:00", …]`（节点本地时间）。

### 2.4 类型字段要求（源码 cronjob_helper.go 核对）

- `shell`：`script` 必填（`scriptMode=input` 写入脚本内容；`library` 从脚本库；`select` 用于容器内脚本）；非容器时 `executor` 默认 `bash`（可选 sh/bash/python/python3）；容器内需 `containerName`（+ 可选 `user`、`command` 解释器）。
- `curl`：`url` 必填（支持逗号分隔多个 URL）。
- `directory`：`sourceDir` 必填；`isDir` 表示目录/文件。
- `website`：`website`（1Panel 网站域名）必填。
- `app`：`appID`（1Panel 已安装应用 key，如 `jenkins`）必填。
- `database`：`dbType`（mysql/mariadb/mysql-cluster/postgresql/postgresql-cluster/mongodb）+ `dbName`（1Panel 数据库记录 id）必填。
- 公共：`retainCopies`（默认 7）、`retryTimes`（0）、`timeout`（秒，默认 3600）、`ignoreErr`。
- **敏感字段**：`secret`（备份压缩密码）可读回但**不返回给浏览器**；更新时若浏览器未提供则沿用 1Panel 当前值。

## 3. 设计

### 3.1 列表（只读）

`POST cronjobs/search` 逐节点并发（复用 P4/P6 只读模式：单节点独立超时、失败隔离、部分成功可见），再合并排序分页：

- 过滤：节点（单节点/全部启用节点）、分组（多选 groupID）、关键字 `info`（名称模糊）、状态（Enable/Disable 前端过滤）；
- 行字段：节点、名称、类型（中文）、分组、周期（描述文本 + 原始 spec）、状态、最近记录状态/时间、执行器/命令摘要、来源信息（网站/应用/DB/目录/URL）。
- 返回：`CronjobListResult(rows, totalMatched, page, pageSize, totalPages, nodesTotal, nodesSucceeded, nodesFailed, nodes[], generatedAt)`，与 P4/P6 结构一致。

### 3.2 详情与编辑

- 详情：`load/info` 返回完整 `CronjobOperate`；对外映射为 `CronjobDetail`：
  - `Fields`：只读展平字段（含敏感字段脱敏）；
  - `Editable`：可编辑模型（不含 secret；保留所有原始 JSON 字段用于更新透传）；
  - `SecretSet`：是否已设置压缩密码（仅布尔）。
- 编辑提交：内核 `cronjob.update`，参数 `{payload:{...}}`。执行阶段处理器先 `load/info` 拿当前 JSON，把 payload 中出现的字段合并回去（含未在 UI 展示的类型专属字段），再 `POST cronjobs/update` —— 避免破坏 snapshot/cleanLog 等类型的原始配置。

### 3.3 写操作与风险

| Kind | 风险（单节点） | 批量 | 说明 |
|---|---|---|---|
| `cronjob.create` | Medium | 不支持（仅单节点） | 创建任务，name/type/spec 必填；成功后提示刷新 |
| `cronjob.update` | Medium | 不支持（仅单节点） | 编辑任务；保留未展示字段与 secret |
| `cronjob.delete` | High | Critical | 可批量；`cleanData`/`cleanRemoteData` 由 UI 勾选（默认 false） |
| `cronjob.enable` / `cronjob.disable` | Medium | Critical | 逐个 POST status |
| `cronjob.run_now` | Medium | Critical | 逐个 POST handle；任务正在执行时该节点失败 |

- 强确认文本：High/Critical 使用内核默认（单节点=节点名，批量="N 个节点"）；批量删除使用处理器覆盖文本 `确认删除 N 个节点共 M 个计划任务`；
- 参数解析（`CronjobTargets`，与容器模块同构）：
  - `cronjobsByNode`：`{nodeGuid: [id, ...]}` 批量按节点映射（UI 多选跨节点时生成）；
  - `ids`：单节点/全局 id 列表（仅当所有选中节点都适用时使用）；
  - `cronjob`：单个 id；
  - 计划阶段校验：至少一个目标；每个选中节点必须有非空目标（批量）；单节点目标数 ≤ `CronjobOptions.MaxBatchJobs`（默认 20）；create/update 必须恰好 1 个节点、1 个任务。
- 执行阶段：单节点逐个提交 1Panel（顺序），任一失败即返回失败（剩余不执行，不回滚），与内核「失败停止」语义一致（节点内也停止）。
- 不做自动重试、不做状态轮询（1Panel 同步返回；页面刷新后以真实列表为准）。

### 3.4 执行记录（只读）

- `cronjobs/search/records`：按任务 id + 时间范围（默认最近 7 天，RFC3339）+ 状态过滤 + 分页；
- 记录字段：id、状态、开始时间、耗时（interval 秒）、taskID、message、记录文件路径（不展示本地路径，仅日志可读）、目标路径；
- 日志：`cronjobs/records/log {id}` 返回文本；后端仅返回纯文本内容（限长 256 KiB，超出截断并提示），**不落库、不写文件**；
- 记录/日志只读，不属于写操作内核；端点 Admin only + CSRF 规则与现有 GET 一致（只读 GET 不需要 CSRF）。

### 3.5 周期助手

- 前端结构化选择 → `CronjobSpec.Build`（Application 纯函数）→ spec 字符串 → `POST cronjobs/next` 预览后 5 次（需要节点，使用当前选中节点或首个启用节点）；
- `CronjobSpec.Describe(spec)` 生成中文描述（失败时显示原始 spec），列表/详情复用。

## 8. 审计

全部写操作由 P5 内核记录：

| Action | TargetType | 说明 |
|---|---|---|
| `operation.executed` / `operation.failed` | `cronjob` | 每节点每条：kind、风险、targetId（任务 id 或 `batch`）、handlerDetail（ids/name/type 等，截断 500） |
| `operation.rejected` | `operation` | 确认失败/重复提交等 |
| `operation.batch` | `operation` | 批量（>1 节点）汇总：节点数、成功/失败、状态 |

- 不记录任务脚本内容/命令全文/密码（secret）；`parameterKeys` 只记键名；
- 记录日志读取不审计（只读），但受 Admin + 节点权限约束。

| 删除任务不可回滚（含备份记录清理选项） | 数据丢失 | High/Critical + 强确认文本 + cleanData 默认关闭 + 审计 |
