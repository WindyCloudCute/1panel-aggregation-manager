## 1. 背景与范围变更

首版（P0–P4）按“只读聚合”设计：总览、资源清单、详情。现确认扩展为**完整 1Panel 管理控制台**，包含写操作、应用商店、容器/网站/数据库/计划任务管理、系统日志、终端、1Panel 更新。

范围变更带来新的架构要求：

1. **写操作层**：确认、审计、风险分级、幂等、异步任务进度、失败处理；
2. **流式通信**：终端（WebSocket 双向）、日志/任务进度（SSE 或轮询）；
3. **安全边界**：写操作二次确认、危险操作强确认、批量操作守卫、终端会话管控；
4. **批量能力**：跨节点操作需顺序执行、失败停止、逐节点审计。

**明确不做（本轮）**：文件管理器、防火墙、监控告警、备份中心、多租户 RBAC（保留后续阶段扩展；如需要再单独立项）。

## 3. 新增共享架构

### 3.1 写操作内核（P5）

```csharp
public enum OperationRisk { Low, Medium, High, Critical }

public sealed record OperationCommand(
    string Key,                 // 如 app.install / container.stop / website.enable
    NodeId NodeId,
    string Title,
    OperationRisk Risk,
    object Payload);            // 具体参数

public sealed record OperationPreview(     // 前端确认弹窗数据
    string Key, string Title, OperationRisk Risk,
    IReadOnlyList<OperationTarget> Targets,
    IReadOnlyList<string> Warnings,
    string? ConfirmText,        // Critical 需要输入的值（如节点名/数量）
    bool RequiresTypedConfirmation);

public interface IOperationService
{
    Task<OperationPreview> PreviewAsync(OperationCommand command, CancellationToken ct);
    Task<OperationResult> ExecuteAsync(OperationCommand command, string? confirmation, CancellationToken ct);
    Task<OperationProgress> GetProgressAsync(string operationId, CancellationToken ct);
}
```

规则：

- 所有写操作必须：**预览 → 二次确认 → 执行 → 审计**；
- `High/Critical` 需输入确认文本（如节点名、目标数量）；`Critical` 额外显示不可回滚警告；
- 执行结果统一 `OperationResult { Success, TaskId, Message, PanelError? }`；1Panel 异步任务（安装/升级/备份）通过 `taskID` 轮询进度；
- 幂等：同一操作 ID 重复提交在 10s 内拒绝（防双击）；
- 审计：`operation.executed`（key/target/风险/结果/耗时），`operation.failed`；
- 原则：**不做自动重试**（写操作重试可能造成重复安装/删除）。

### 3.2 流式通信层（P6/P11）

- WebSocket 桥：浏览器 ↔ PanelFleet（ASP.NET Core WS 端点）↔ 1Panel WS 端点；
- 鉴权：仅 Admin 会话；连接建立时校验节点权限；
- 终端：本地打包 xterm.js（不引 CDN），固定尺寸/心跳/断线提示/会话超时（默认 30 分钟无操作断开）；
- 审计：终端会话开始/结束、节点、操作者、时长；**不记录输入内容**；
- 日志流：SSE 或 WS，支持 tail/follow、关键字过滤；停止即断开。

### 3.3 批量操作守卫（P12 等）

- 默认单节点；批量必须显式选择节点列表并显示目标数量；
- 顺序执行（避免并发升级/重启打满节点），逐节点确认结果；
- 失败即停止后续节点（默认），已执行节点不回滚并记录；
- 批量上限 `Operations:MaxBatchNodes`（默认 10）；
- 逐节点审计 + 一条批次汇总审计。

## 4. 1Panel 更新（P12）专项设计约束

用户已确认**允许批量升级**，但必须满足：

1. 先对所选节点执行版本检查，展示当前版本/目标版本/更新说明；
2. 危险确认：输入「节点数量」或节点名列表（Critical）；
3. 预检：节点在线、1Panel 版本可读、磁盘空间（若接口可查）；不满足的节点不允许加入批次；
4. 顺序执行：一次只升级一个节点，轮询任务进度（或等待面板重启后健康检查）；
5. 失败停止：某节点升级失败/超时，停止后续节点并保留结果；
6. 升级后健康检查：重新探测 `/dashboard/base/os`，失败标记「升级后不可达」；
7. 审计：每节点一条 + 批次一条，含版本变化/结果/耗时；
8. 文档明确**无自动回滚**（1Panel 升级失败需人工介入）。

## 6. 测试与真实验收原则

- 假面板扩展写接口：安装/卸载/升级/容器启停/任务进度/WS 终端（可用假 WS 服务）；
- 集成测试覆盖：确认流程、权限、审计、批量顺序与失败停止；
- 真实节点验收只做**低危操作**：停止/启动测试容器、创建/删除测试库、创建/删除测试计划任务、安装一个无状态测试应用（如需）；**不在真实节点执行 1Panel 升级**，批量升级用假面板/独立测试机验证；
- 终端验收：真实节点打开 shell 执行 `echo`/`uptime` 等只读命令；不在真实节点执行破坏性命令。

## 7. 风险与开放问题

| 风险 | 影响 | 对策 |
|---|---|---|
| 写操作误删/误停 | 生产事故 | 二次确认 + Critical 输入确认 + 审计 + 默认单节点 |
| 批量升级断电/失败 | 节点面板不可用 | 顺序执行、失败停止、升级前提示无回滚、要求选择维护窗口 |
| 终端被滥用 | 安全风险 | Admin only、会话超时、审计、可配置禁用（`Terminal:Enabled=false`） |
| 1Panel API 版本差异 | 写接口 404/参数变化 | 每阶段真实探测 + 假面板契约测试 + 降级提示 |
| 异步任务进度接口差异 | 安装/升级进度缺失 | 轮询 taskID；无进度接口时展示「已提交，稍后刷新」 |
| WebSocket 反向代理 | 终端/日志连不上 | 部署文档要求 Upgrade 头透传；提供直连回退 |
| 批量操作范围 | 风险放大 | 批次上限、逐节点确认、失败停止、默认单节点 |
