## 1. 目标与范围

P5 在写操作内核（docs/09）之上交付**应用商店**：

1. 真实接口探测（只读）：应用商店搜索/标签/应用详情/版本参数、已安装应用列表/详情/参数、升级版本、卸载关联检查、异步任务状态；

### 2.4 写接口请求结构（源码核对，未真实调用）

- 安装 `POST api/v2/apps/install`（`request.AppInstallCreate`）：
  - 必填：`appDetailId`（应用版本详情 ID，来自 #4 的 `id`）、`name`（安装/容器名称）；
  - 常用：`params`（键值对，键来自 #4 的 `formFields[].envKey`）、`taskID`（客户端生成的 UUID，用于任务日志）、
    `advanced`、`cpuQuota`、`memoryLimit`、`memoryUnit`（M/G）、`containerName`、`allowPort`、`specifyIP`、
    `restartPolicy`（always / unless-stopped / no / on-failure）、`pullImage`、`gpuConfig`、`editCompose`、`dockerCompose`、`webUI`；
  - 响应 `data` 为 `model.AppInstall`（含新 `id`），安装动作异步执行。
- 卸载/升级/启停 `POST api/v2/apps/installed/op`（`request.AppInstalledOperate`）：
  - 必填：`installId`、`operate`；
  - 卸载：`operate=delete`，可选 `forceDelete`、`deleteBackup`、`deleteDB`、`deleteImage`、`taskID`；
  - 升级：`operate=upgrade`，`detailId`（目标版本详情 ID）、`backup`、`pullImage`、`deleteImage`、`dockerCompose`（可选自定义编排）、`taskID`。
- 修改参数 `POST api/v2/apps/installed/params/update`（`request.AppInstalledUpdate`）：
  - 必填：`installId`、`params`；可选 `advanced` 及容器高级配置（`cpuQuota`/`memoryLimit`/`memoryUnit`/`containerName`/`allowPort`/`specifyIP`/`restartPolicy`/`editCompose`/`dockerCompose`）；
  - 响应无 `taskID`（服务端内部异步，UI 展示「已提交」并刷新已安装列表）。
- 参照前端实现：`frontend/src/views/app-store/detail/form/index.vue`、`installed/delete/index.vue`、`installed/upgrade/index.vue`、`installed/detail/index.vue`（commit `65243c68`）。

### 2.5 探测限制与注意点

1. **写接口未真实执行**（安全红线）：参数结构来自源码与前端调用，集成测试用假面板覆盖。
2. **搜索响应为 gzip 可能**：`apps/search` 使用 `SuccessWithDataGzipped`；探测工具未发送 `Accept-Encoding` 时返回明文。PanelFleet 客户端需确保解压（HttpClient 默认不压缩，服务端按请求头决定；契约测试覆盖 gzip 场景已有基础设施）。
3. **`HttpPort` 大小写差异**：已安装详情 JSON 键为 `HttpPort`（首字母大写），列表为 `httpPort`；DTO 用大小写不敏感反序列化。
4. **时间格式**：部分字段是 RFC3339（含纳秒/时区），部分零值 `0001-01-01T00:00:00Z`；DTO 用 `string` 宽松解析，应用层转为 `DateTimeOffset?`。
5. **升级版本接口可能返回 `null`**：表示已是最新或无可用版本，UI 明确提示，不视为错误。
6. **删除检查返回 `null`**：无关联资源，UI 不展示警告。
7. **任务状态**：1Panel 任务查询按 `taskID` 过滤（本次探测验证 `taskID` 过滤生效）；任务最终状态 `Success`/`Failed`，执行中为 `Executing`/`Waiting`。任务日志内容（`/logs/tasks/read`）不在 P5 展示，只展示状态。
8. **鉴权**：API Key 需具备应用商店读/写权限（RBAC 未逐项验证）；401/403 由客户端映射为明确提示。
9. **版本漂移**：字段按 v2.3.2 锁定，DTO 全部宽松解析（忽略未知字段、缺失不抛异常），新增字段向后兼容。

## 5. 写操作处理器（IOperationHandler）

| Kind | 处理器 | 单节点风险 | 批量（>1 节点）风险 | 1Panel 调用 |
|---|---|---|---|---|
| `app.install` | `AppInstallOperationHandler` | Medium | **Critical** | `POST apps/install` |
| `app.uninstall` | `AppUninstallOperationHandler` | **High**（输入节点名确认） | **Critical** | `POST apps/installed/op`（operate=delete） |
| `app.update` | `AppUpdateOperationHandler` | **High**（单节点） | **Critical** | `POST apps/installed/op`（operate=upgrade） |
| `app.params_update` | `AppParamsUpdateOperationHandler` | Medium | **Critical** | `POST apps/installed/params/update` |
| `app.batch_upgrade` | `AppBatchUpgradeOperationHandler` | **High**（单应用） | **Critical** | `POST apps/installed/op`（逐节点逐应用串行，operate=upgrade） |

处理器约定：

- `PlanAsync`：只做参数校验与预览，不产生副作用；返回 `Title`/`Summary`/`Risk`/`Targets`/`Warnings`/`TargetType="app"`；
  Summary 包含节点数、应用名、安装 ID、关键参数键名/选项（**不包含密码值**）；
- 批量风险提升为 Critical，强确认文本由内核按默认规则生成（单节点 High = 节点名；批量 = `N 个节点`）；`app.batch_upgrade` 使用自定义确认文本「升级 N 个节点 M 个应用」；
- 升级版本列表按 1Panel 契约升序返回；服务层按版本号数字段兜底排序，UI 默认选中最后一个（最新）版本，批量升级同样取最新版本；
- `ExecuteAsync`：单节点执行，`Success=false` 或抛异常由内核转失败结果；成功时返回 1Panel 异步 `TaskId` 与中文消息；
- 审计：内核自动写 `operation.executed`/`operation.failed`/`operation.rejected`/`operation.batch`，`TargetType="app"`，
  `TargetId` = 安装名称（安装）或 `installId`（卸载/升级/改配置）；内核审计 `DetailJson` 记录 `operationId/kind/title/risk/nodeName/targetId/success/message/taskId/durationMs`（**不含参数值**；当前内核未转写 handler 的 Step.DetailJson，参数键名只在执行结果视图展示）；
- 不做自动重试/回滚（内核约束）；安装/升级/卸载失败需用户重新预览确认或手动清理。

各操作警告（Plan.Warnings）：

- 安装：下载镜像耗时、异步任务提交后需刷新、不会自动回滚、无参数时使用默认配置；
- 卸载：不可回滚、需确认已备份；勾选删库/删备份/删镜像时追加高危警告；
- 升级：容器重建短暂中断、备份开关状态提示、不支持自动回滚、自定义编排覆盖提示；
- 批量升级：按节点顺序串行执行，任一应用失败会停止后续所有升级；不自动重试、不回滚；
- 修改配置：容器重建/重启、端口/密码变更需同步客户端、不支持自动回滚、高级配置提示。

## 6. 任务状态展示

- 1Panel 写操作异步执行，客户端传入 `taskID`（UUID）用于任务关联；任务状态通过 `POST api/v2/logs/tasks/search {taskID}` 查询。
- 页面在操作执行成功后启动 `AppTaskProgress` 组件（每 3 秒轮询，最多约 20 分钟），展示：
  - 任务徽标（执行中/成功/失败）、任务号、任务名、结束时间、`errorMsg`；
  - 终态后自动回调刷新「已安装应用」列表；
  - 查询失败不视为操作失败（任务本身在 1Panel 侧执行），继续重试并提示。
- `app.params_update` 没有客户端可指定的 `taskID`：执行结果展示「已提交」，提示刷新已安装列表；页面仍会刷新列表一次。
- 兜底：任务查询接口不可用/超时，展示「已提交，状态未知」并以已安装列表状态为准。

## 7. 错误处理矩阵

| 场景 | 用户可见提示 | 处理 |
|---|---|---|
| 节点不存在 | 「节点不存在」 | `NodeNotFoundException` → Web 404 / 页面提示 |
| 节点已禁用 | 「节点 X 已禁用，请先在节点页启用」 | `AppStoreException(Unsupported)` → Web 502 / 页面提示 |
| 1Panel 鉴权失败 | 节点返回 401 对应提示（含节点名，不含密钥） | `PanelErrorKind.Unauthorized` → Web 502 |
| 网络/TLS/超时 | 节点不可达/超时提示 | `Network`/`Tls`/`Timeout` → Web 502 |
| 1Panel 内部错误 | 1Panel 返回 message | `PanelServerError` → Web 502 |
| 参数不合法（1Panel code 400） | 1Panel message（如「参数错误: xx 为必填」） | `Validation` → Web 400 |
| 预览参数缺失/非法（本地校验） | 具体字段提示（中文） | `OperationValidationException` → 400，不生成确认 Token |
| 确认文本错误/Token 过期/重复提交 | 内核确认错误提示 | `OperationConfirmationException` → 409，审计 `operation.rejected` |
| 写操作执行失败 | 逐节点失败原因（不重试、不回滚） | 内核失败结果 + `operation.failed` 审计 |
| 任务查询失败 | 「任务状态查询失败（任务本身不受影响）」 | 继续轮询/降级到「已提交」 |
| 升级版本为空 | 「没有可用的升级版本」 | 不发起写操作 |
| 删除检查为空 | 无关联资源，不展示警告 | `data:null` 视为空列表 |

## 10. 审计与安全

- 审计由内核统一写入：`operation.executed`/`operation.failed`/`operation.rejected`/`operation.batch`；
- 应用商店写操作 `TargetType="app"`，`TargetId` 为安装名或安装 ID；内核审计 `DetailJson` 含 `kind/title/risk/nodeName/targetId/success/message/taskId/durationMs`（不写入参数值；参数键名仅出现在执行结果 `DetailJson` 与界面中，不落审计）；
- 密码/密钥类参数值不进入审计、不进入操作结果 `DetailJson`、不进入日志；UI 密码输入默认隐藏；
- API Key 只在 `INodeSecretProtector` 解密后由客户端签名处理器短暂使用，不进入 DTO/日志/响应；
- 页面与端点 Admin only；真实节点不执行写操作（本阶段探测只读）。

## 15. 限制与风险

1. 写接口未在真实节点验证（安全约束），依赖源码结构 + 假面板契约；若 1Panel 小版本字段变化，可能返回「参数错误」，需按提示修正参数；
2. `params_update` 无客户端任务号，只能展示「已提交」并刷新列表；
3. 应用安装/升级可能耗时较长（镜像下载），内核单节点超时预算默认 120 秒；超时后任务可能仍在 1Panel 侧执行，页面提示以任务状态/已安装列表为准；
4. 批量操作使用内核顺序执行 + 失败停止，已执行节点不回滚；
5. 应用图标不展示（需逐节点鉴权代理），只用文字/标签；
6. 应用商店数据依赖节点自身同步状态，可能滞后；UI 提示可在 1Panel 同步；
7. 已安装列表 `canUpdate` 依赖 `checkUpdate` 参数（较慢），UI 默认不主动全量检查，进入升级弹窗时按应用查询 `update/versions`；
8. 「可升级」tab 聚合时每个启用节点最多取前 100 个已安装应用（避免 N×K 请求爆炸），节点应用数 >100 时可能漏列；升级版本按应用逐个查询，节点/应用较多时首屏较慢（已有骨架 loading，未做并发限流）；
9. 详情抽屉暂无 README/分类标签字段（Client `AppStoreDetail` 未映射 tags/readme），当前以描述、类型与官网/文档/GitHub 链接替代；
10. 已安装状态下详情抽屉只显示「已安装」标记，不提供同一入口的重装；如需重装请到 1Panel 操作或后续加二级入口。

## 16. 验收步骤（可复现）

1. 启动 PanelFleet（Lead 接线后），Admin 登录，侧边栏进入「应用商店」；
2. 选择节点 → 应用商店出现分类与卡片；搜索关键字/切换分类 → 列表变化；
3. 点应用卡片「详情」→ 右侧抽屉只展示应用信息（无参数表单）；点「安装应用」→ 进入独立安装向导（选择节点 → 参数表单 → 预览弹窗 → 确认执行 → 结果视图 + 任务状态轮询 → 已安装列表出现应用，假面板环境）；
4. 已安装区点击「修改配置」→ 修改端口 → 预览 → 确认执行 → 结果 + 审计记录（`operation.executed`，`targetType=app`）；
5. 点击「升级」→ 选择版本/备份选项 → 预览（High，需输入节点名）→ 执行 → 任务状态；
6. 切「可升级」tab → 聚合各节点可升级应用 → 勾选多节点应用 → 批量升级 → 确认文本「升级 N 个节点 M 个应用」→ 执行后按节点展示结果，任一失败即停止，审计含 `operation.batch`/`operation.executed`/`operation.failed`；
7. 点击「卸载」→ 关联资源检查 → 勾选选项 → 预览（High，需输入节点名）→ 错误文本 409 → 正确文本执行成功；
8. 审计页可查到 `operation.executed`/`operation.batch`/`operation.rejected`，且详情不含密码值；
9. 非管理员/未登录访问 `/api/appstore/*`、`/appstore` 被拒绝；真实节点只做只读浏览。
