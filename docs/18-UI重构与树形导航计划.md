# 18 · UI 重构与树形导航详细设计（M-UI 计划）

状态：设计已定稿，进入实施（2026-11-17）
关联：`docs/03-阶段计划.md`、`docs/08-功能扩展路线图.md`、`docs/research/ui-design-*.md`

## 1. 背景与目标

### 1.1 现状问题
- 管理页导航交互不统一：`/databases`、`/resources` 已是「左树右区」，而 `/containers`、`/websites`、`/cronjobs`、`/appstore`、`/logs`、`/panelupdate` 仍是顶部「节点下拉框」。
- 下拉框适合浏览、不适合定位：操作某个资源前要先知道它在哪个节点，再切节点、再查找；新建入口挂在「全部节点」时归属不明确。
- 视觉偏「死板」：卡片无圆角层次、页面切换无过渡、表格行无悬停反馈、弹窗/抽屉生硬、空态与加载态缺失。

### 1.2 目标
1. 所有管理页统一为「**左树 + 右工作区**」：树能一眼看到 节点 → 资源 的归属，点叶子直接看详情/操作。
2. **新建一律先选节点**：任何创建动作（容器、网站、数据库、计划任务、应用安装）第一步是选择目标节点；从某节点上下文发起时预填并锁定，不允许跨节点创建。与后端「写操作仅单节点」的约束一致。
3. **现代化圆角 UI + 丰富动效**：统一圆角/阴影/渐变/玻璃质感设计令牌；页面、卡片、表格、抽屉、弹窗、树展开、骨架屏都有克制的过渡动效，并支持 `prefers-reduced-motion`。
4. 深色主题：顶栏可切换、记忆选择；两套主题共用语义令牌。

### 1.3 非目标
- 不改任何后端 API、写操作内核、审计与安全语义。
- 不引入前端框架、不新增外部 CDN/字体依赖（内网可用）。
- 不重写业务组件的数据加载逻辑，只重排布局与交互入口。

### 2.3 形状与阴影
| 令牌 | 值 |
| --- | --- |
| `--radius-sm` | `8px`（小按钮/输入） |
| `--radius-md` | `12px`（按钮/输入/树行） |
| `--radius-lg` | `16px`（卡片/表格容器/树） |
| `--radius-xl` | `22px`（弹窗/抽屉/大面板） |
| `--shadow-sm` | `0 1px 2px rgba(15,23,42,.05)` |
| `--shadow-md` | `0 6px 20px rgba(15,23,42,.08)` |
| `--shadow-lg` | `0 18px 48px rgba(15,23,42,.16)` |
| `--glass` | `backdrop-filter: blur(14px); background: color-mix(in srgb, var(--panel) 78%, transparent)` |

组件规范：
- 卡片/表格容器：`radius-lg` + `1px solid var(--border)` + `shadow-sm`，悬停时 `shadow-md`。
- 按钮：`radius-md`，主按钮渐变（`linear-gradient(135deg, var(--primary), var(--primary-dark))`），按下 `scale(.97)`。
- 表格：表头 sticky、行悬停 `--panel-hover`、选中行 `--primary-soft`、单元格间距 12px。
- 弹窗：`radius-xl` + `shadow-lg`；抽屉：右侧滑入、顶部圆角、`radius-xl`。
- 侧边栏/顶栏：深色/玻璃质感，导航 active 用胶囊高亮。

### 2.4 动效
| 令牌 | 值 |
| --- | --- |
| `--ease-out` | `cubic-bezier(.22,1,.36,1)` |
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` |
| `--dur-fast` | `120ms` |
| `--dur` | `200ms` |
| `--dur-slow` | `320ms` |

必须实现的动效（CSS-only，禁止新增 JS 动画库）：
1. 页面进入：内容区 `fade + translateY(6px)` 200ms。
2. 卡片/表格行悬停：背景/阴影 120–150ms；卡片 `translateY(-2px)`。
3. 按钮按压：`scale(.97)` 120ms；主按钮 hover 亮度提升。
4. 抽屉：滑入 260ms `--ease-out`；弹窗：`scale(.96→1)+fade` 200ms；遮罩 fade。
5. 树：`grid-template-rows 0fr→1fr` 220ms；chevron 旋转 180ms；叶子 hover 位移 1px。
6. 骨架屏：`shimmer` 1.4s 循环；列表加载使用骨架而非空白。
7. 提示/toast：右下角滑入 200ms。
8. `@media (prefers-reduced-motion: reduce)` 下全部动画/过渡关闭或缩短。

### 2.5 字体与图标
- 正文：`"Microsoft YaHei", "PingFang SC", "Segoe UI", system-ui, sans-serif`；等宽/终端：`"JetBrains Mono", "Cascadia Code", Consolas, monospace`。不引入外链字体。
- 图标：内联 SVG（16/18/20px，`stroke=currentColor`），统一线性风格；**禁止 emoji 作为结构图标**。

## 3. 布局与导航规范

### 3.1 页面骨架
```
.page-header（标题 + 操作按钮）
.workbench
  ├─ <aside class="workbench-tree">  ← NavTree / 页面左树（≈300px，独立滚动）
  └─ <section class="workbench-main"> ← 工具栏 + 表格/详情/空态
```
- `>= 1024px`：左树固定 300px；`< 1024px`：左树收进抽屉，顶部提供「节点/资源」按钮。
- 左树与右区各自滚动，页面不整体横跳。

### 3.2 树数据规则
- 根：`全部节点`（聚合视图，仅只读/汇总/批量）。
- 一级：启用节点（状态点 + 1Panel 版本/地址）；禁用节点置灰不可选。
- 二级起按页面：容器/Compose、分组→网站、实例→库、任务、已安装应用、日志类型、升级勾选。
- **懒加载**：节点首次展开时才请求该节点子项（复用现有 service），不首屏全量拉取；加载中显示 spinner，失败显示「加载失败」并可重试。
- 选中态：`nodeId` 存 URL query（`?nodeId=...&id=...`），可深链回跳；同时记忆到 `localStorage`（`pf.tree.{page}`），无 query 时恢复上次选择。
- 键盘：树行可 Tab 聚焦，Enter/Space 展开或选中，`aria-expanded`/`aria-selected` 正确。

### 3.3 新建流程（强制）
1. 点击任意「新建/创建/安装」按钮 → 打开对话框，**第一步为节点选择**（下拉或小型节点列表 + 搜索），显示节点状态；不可用节点禁用。
2. 从某节点上下文（树选中该节点/资源）发起时，节点预填并锁定（只读展示），不允许改为其他节点。
3. 未选节点时确认按钮禁用；提交时后端仍按单节点写操作执行并审计。
4. 批量操作（如 1Panel 批量升级）保持「显式勾选 ≥2 节点 → 逐节点顺序执行 → 失败即停」的既有安全模型，入口改为树的勾选模式。

### 3.4 状态完备
每个列表/树必须实现：加载态（骨架/spinner）、空态（说明 + 主 CTA）、错误态（错误文案 + 重试）、禁用态。不得只做 happy path。
