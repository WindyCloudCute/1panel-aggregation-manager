## 1. 目标与非目标

**目标**：让工具具备「可登录、可存节点、可验证节点可用性」的最小平台能力。

1. 仅通过 **Pocket ID（OIDC）** 登录，无本地账号密码；
2. SQLite 持久化节点、分组、审计、设置；
3. 节点 API Key 加密存储，任何页面/日志/API 不返回明文；
4. 节点 CRUD + 连接测试 + 能力/版本探测；
5. 后台健康巡检，状态可视化；
6. 页面骨架（导航、布局、错误页、审计页）；
7. 为 P3 聚合总览提供稳定的节点存储与客户端工厂。

**非目标**：聚合总览（P3）、资源清单（P4）、写操作、多角色细粒度权限、监控历史、终端/文件。

## 3. 认证与授权（OIDC Only）

### 3.1 提供方与流程

- 提供方：**Pocket ID**，Authority = `https://auth.example.com`（发现文档 `/.well-known/openid-configuration`）。
- 流程：Authorization Code + **PKCE**（`UsePkce=true`），confidential client。
- 回调路径：`/sso/OIDC/Callback`（与 Pocket ID 中配置保持一致，可配置）。
- 登出回调：`/sso/OIDC/SignedOut`；登出优先本地 Cookie 注销，若发现文档提供 `end_session_endpoint` 则尝试 RP-Initiated Logout。

### 3.2 配置项（`Oidc` 节）

| 配置键 | 默认值 | 必填 | 说明 |
|---|---|---|---|
| `Oidc:Authority` | — | 是 | Pocket ID 基地址（https） |
| `Oidc:ClientId` | — | 是 | Pocket ID 应用 ID |
| `Oidc:ClientSecret` | — | 是 | **只通过环境变量/用户机密注入，禁止提交** |
| `Oidc:CallbackPath` | `/sso/OIDC/Callback` | 是 | 必须以 `/` 开头 |
| `Oidc:RedirectUri` | 空（按请求推导） | 否 | 显式指定 redirect_uri；反向代理/外部访问时必填，且必须与 Pocket ID 注册值一致 |
| `Oidc:SignedOutCallbackPath` | `/sso/OIDC/SignedOut` | 否 | 登出回调 |
| `Oidc:Scopes` | `openid profile email` | 否 | 若 Pocket ID 提供 groups，可加 `groups` |
| `Oidc:RequireHttpsMetadata` | `true` | 否 | 测试环境才允许 false |
| `Oidc:RoleClaimType` | `groups` | 否 | 角色/组 claim 名称（预留） |
| `Oidc:AdminRoles` | 空数组 | 否 | claim 命中即管理员（P2 预留） |
| `Oidc:ReadOnlyRoles` | 空数组 | 否 | 只读角色（P2 预留，不启用） |

环境变量命名：`Oidc__ClientId`、`Oidc__ClientSecret`、`Oidc__Authority`。

### 3.3 白名单与角色

- **授权由 Pocket ID 负责**：谁能访问该 OIDC 客户端、用户属于哪些组，由 IdP 管理；应用默认不维护邮箱白名单。
- 可选的额外防线：`Auth:AllowedEmails` / `Auth:AllowedSubjects`（默认空 = 允许所有已认证用户；配置后必须命中其一）。
- 角色映射（P2 启用）：`Oidc:RoleClaimType`（默认 `groups`）+ `Oidc:AdminRoles`：
  1. `AdminRoles` 为空 → 所有已认证用户视为管理员（单管理员工具）；
  2. `AdminRoles` 非空 → 仅 `groups` claim 命中者为管理员，其余 `403 /auth/denied`；
  3. 若配置了 `AllowedEmails/Subjects`，还需命中白名单（双重防线）。
- 命中后追加 `app_role=admin` claim；P2 只有 `Admin` 策略；`Oidc:ReadOnlyRoles` 仅登记不生效（P3 再启用）。
- **Fail-closed**：Authority/ClientId/ClientSecret 缺失或非法、CallbackPath 非法、`RedirectUri` 非绝对 URL → 应用启动失败并打印明确原因（不含密钥）。
- 服务端启动时打印（脱敏）：Authority、ClientId 前 6 位、回调地址、是否启用组映射、白名单数量。

### 3.4 Cookie 与 DataProtection

- Cookie：名称 `PanelFleet.Auth`；`HttpOnly=true`；`SameSite=Lax`；`SecurePolicy=SameAsRequest`（HTTPS 部署时自动 Secure）；`ExpireTimeSpan=8h`；`SlidingExpiration=true`；未认证 challenge → OIDC。
- DataProtection：密钥持久化到 `<DataDirectory>/keys`；Windows 下追加 `ProtectKeysWithDpapi()`；非 Windows 记录警告（P5 再引入证书保护）。
- **注意**：DPAPI 绑定服务运行账户，数据目录不可跨账户/跨机直接复制；换机需重新录入节点 Key。

### 3.5 登录/登出/错误页

| 路由 | 方法 | 行为 |
|---|---|---|
| `/login` | GET | 匿名页，展示产品名 + 「使用 Pocket ID 登录」按钮 |
| `/auth/login` | GET | 触发 OIDC Challenge（仅此一个入口） |
| `/logout` | POST | 防伪令牌校验 → Cookie 注销（可选 RP 登出）→ 302 `/login` |
| `/auth/denied` | GET | 403 页面：说明「账号不在白名单」 |
| `/error` | GET | 500 页面：traceId + 重试说明（不暴露堆栈） |

- 全站除 `/login`、`/auth/*`、`/healthz`、`/readyz`、`/error`、静态资源外，一律 `RequireAuthorization("Admin")`。
- Blazor 端使用 `<AuthorizeRouteView>` + `RedirectToLogin` 组件；未登录访问任意页跳 `/login`。

## 4. 数据层

### 4.1 数据目录与连接

- `<DataDirectory>`：默认 `%ProgramData%\PanelFleet`；覆盖变量 `PanelFleet__DataDirectory`。
- 子目录：`panel.db`、`keys/`、`logs/`。
- 连接串：`Data Source=<DataDirectory>/panel.db`；启动时设置 `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000;`。
- 迁移：`Database.MigrateAsync()`；若存在待应用迁移且数据库文件已存在，先复制为 `panel.db.bak-<UTC时间戳>`（最多保留最近 5 份）。

## 5. 密钥保护

- 使用 `IDataProtectionProvider.CreateProtector("PanelFleet.NodeApiKeys.v1")`。
- 存储：`ApiKeyProtected = Base64(protector.Protect(apiKey))`；`ApiKeyHint` 取 API Key 末 4 位（长度 <4 时固定 `••••`）。
- 解密只在两处：连接测试/巡检创建客户端前；其他任何层禁止调用 `Unprotect`。
- 日志：`NodeSummary` 只有 `ApiKeyHint`；异常/审计/调试日志禁止输出 Key。
- 单元测试：protector 往返、篡改密文抛异常、Hint 规则、`NodeSummary` JSON 不含密文。

## 6. 节点管理

### 6.1 REST API（均要求 `Admin` 策略）

| 方法 | 路径 | 说明 | 成功 | 主要错误 |
|---|---|---|---|---|
| GET | `/api/nodes` | 节点列表（摘要，无密文） | 200 | 401 |
| POST | `/api/nodes` | 新增节点 | 201 + Location | 400/409 |
| GET | `/api/nodes/{id}` | 节点详情 | 200 | 404 |
| PUT | `/api/nodes/{id}` | 更新节点（ApiKey 为空表示不变） | 200 | 400/404/409 |
| DELETE | `/api/nodes/{id}` | 删除节点 | 204 | 404 |
| POST | `/api/nodes/{id}/test` | 测试已保存节点并回写探测结果 | 200 | 404/409 |
| POST | `/api/nodes/test` | 保存前测试（不落库） | 200 | 400 |
| GET | `/api/node-groups` | 分组列表 | 200 | 401 |
| POST | `/api/node-groups` | 新建分组 | 201 | 400/409 |
| PUT | `/api/node-groups/{id}` | 重命名/排序 | 200 | 400/404 |
| DELETE | `/api/node-groups/{id}` | 删除分组（节点 GroupId 置空） | 204 | 404 |
| GET | `/api/audit?take=100` | 最近审计 | 200 | 400 |
| GET | `/api/antiforgery/token` | 获取防伪令牌（供非 Blazor 调用） | 200 | 401 |

- 变更类请求要求 `X-CSRF-TOKEN` 头；Blazor 组件直接调用 Application 服务，不经过 HTTP，因此无需防伪令牌。
- 响应错误统一 `ProblemDetails`：`{ type, title, status, detail, errors? }`。
- 请求/响应 DTO：
  - `CreateNodeRequest { Name, BaseUrl, SecurityEntrance?, ApiKey, AuthMode, TlsPolicy, GroupId?, Tags[], Remark?, IsEnabled }`
  - `UpdateNodeRequest` 同上，`ApiKey` 可空；
  - `SecurityEntrance`：1Panel 安全入口（单个路径段，如 `myentrance`），仅保存备用，**不拼入 API 地址**；用于以后从工具跳转面板 UI。
  - `NodeSummary { Id, Name, BaseUrl, GroupId, GroupName, Tags, Remark, ApiKeyHint, AuthMode, DetectedAuthMode?, TlsPolicy, PanelVersion, Capabilities, Health, HealthMessage, LastCheckedAt, IsEnabled }`
  - `NodeTestResult { Reachable, Authorized, LatencyMs, DetectedAuthMode?, ClockOffsetSeconds?, PanelVersion, Os, ErrorKind?, ErrorMessage? }`
- 校验规则：
  - Name：去空格后 1..64，唯一（忽略大小写）；
  - BaseUrl：绝对 `http/https`，无 query/fragment，末尾 `/` 归一化；唯一；
  - ApiKey：新增必填、8..512 字符、非空白；
  - Tags：≤10 个，每个 1..32；
  - Remark ≤500；
  - GroupId 必须存在或为 null；
  - AuthMode/TlsPolicy 必须在枚举范围。
- 状态码：`400` 参数错误（含字段错误字典）；`404` 节点/分组不存在；`409` 名称或 BaseUrl 冲突；`401/403` 认证/授权。

### 6.2 连接测试与能力探测

- 使用 P1 的 `IPanelClientFactory` + `CapabilityProbe`：
  1. 构造 `NodeDescriptor`（含解密后的 Key、AuthMode、TLS 策略、已保存的 ClockOffset）；
  2. `GET /api/v2/dashboard/base/os`；
  3. 成功 → `Reachable/Authorized=true`，记录 `LatencyMs`、`DetectedAuthMode`、`ClockOffsetSeconds`、`PanelVersion`、`Os`；
  4. 失败 → 返回 `PanelErrorKind` 与中文提示（不抛异常）。
- 已保存节点测试成功后回写：`PanelVersion`、`DetectedAuthMode`、`ClockOffsetSeconds`、`Capabilities |= Dashboard`、`HealthStatus=Online`、`LastCheckedAt/LastSeenAt=UTC now`；记录审计 `node.tested`。
- 保存前测试不落库、不写审计；用于表单「测试连接」。
- 超时预算：10 秒；TLS 自签需用户显式选择，测试成功后在表单显示风险提示。

## 7. 健康巡检

- `NodeHealthMonitor : BackgroundService`：
  - 启动后延迟 5s 执行首轮；之后 `PeriodicTimer`（默认 60s，可配 `Health:IntervalSeconds`）。
  - 每轮取 `IsEnabled=true` 的节点，全局并发 4（`Health:MaxConcurrency`），每节点超时 8s（`Health:TimeoutSeconds`）。
  - 每节点：解密 Key → 创建客户端（`using`）→ `CapabilityProbe` → 更新状态与探测元数据。
  - 状态规则：
    | 结果 | HealthStatus |
    |---|---|
    | 成功 | Online |
    | Unauthorized / Forbidden | Offline（消息：鉴权失败/白名单） |
    | Network / Tls / Timeout | Offline |
    | NotFound / Protocol / PanelServerError | Degraded |
    | Canceled（关停） | 不改状态 |
  - 并发保护：同一轮未结束时下一 tick 跳过（`SemaphoreSlim(1,1)`）。
  - 状态变化写结构化日志（节点、旧状态、新状态、耗时、错误分类）；不逐次写审计。
  - 巡检不阻塞请求线程；结果供 P3 总览使用。

### 8.3 Antiforgery 与 SignalR

- Cookie 认证 + Blazor Server SignalR：SignalR 连接要求已认证 Cookie；登录页匿名可加载。
- 登出使用 `<form method="post" action="/logout">` + `<AntiforgeryToken />`。
- REST 变更端点要求 `X-CSRF-TOKEN`；`GET /api/antiforgery/token` 返回令牌（仅认证后）。
- 反向代理部署时启用 ForwardedHeaders（`ASPNETCORE_FORWARDEDHEADERS_ENABLED=true`），否则 Cookie Secure/回调地址会错。

## 13. 验收步骤（P2 完成时）

1. 配置环境变量：`Oidc__ClientId`、`Oidc__ClientSecret`、`Oidc__Authority=https://auth.example.com`、`Auth__AllowedEmails__0=<邮箱>`；

3. `dotnet run --project src/PanelFleet.Web` → 打开 `http://127.0.0.1:5188` → 跳转 Pocket ID → 登录后回到 `/`；
4. 用非白名单账号登录 → 看到 `/auth/denied`；
5. 添加真实 1Panel 节点 → 「测试连接」显示延迟/版本/鉴权方式 → 保存 → 列表只显示 Key 末 4 位；

8. 重启应用 → 节点仍可用（DataProtection keys 生效）；

## 14. 风险与未决问题

| 风险/问题 | 影响 | 对策/待确认 |
|---|---|---|
| 回调地址与部署方式不一致 | 外部浏览器登录失败 | 你确认的回调是 `http://127.0.0.1:5188/sso/OIDC/Callback`，但部署选择“内网 IP + 反向代理 HTTPS”。**必须在 Pocket ID 注册外部地址（如 `https://<域名>/sso/OIDC/Callback`），并通过 `Oidc:RedirectUri` 显式指定同一地址**；实现同时支持两者，验收前需对齐 |
| 授权完全交给 IdP | Pocket ID 侧误放行即全权访问 | 文档明确：Pocket ID 客户端应只授权给运维组成员；应用可选白名单作为第二道防线 |
| Pocket ID `groups` claim 名称/格式 | 角色映射不生效 | 默认 `groups`；实现时按 ID Token 实际 claim 名称可配 `Oidc:RoleClaimType` |
| 监听地址/HTTPS | Cookie Secure、回调地址 | 默认 `127.0.0.1:5188` HTTP；若反向代理需提供外部访问地址并启用 ForwardedHeaders |
| DPAPI 绑定账户 | 数据目录不可迁移 | 文档明确；换机重新录入节点 |
| SQLite 单写者 | 并发写少（单管理员） | WAL + 迁移前备份 |
| Blazor Server 断线重连 | 登录态/页面状态 | 依赖 Cookie；P3 再优化 |
| OIDC 无 IdP 时无法自动测试 | 流程难回归 | 单元测 AllowListEvaluator；集成测试用测试认证；真登录手工验收 |
| 真实 1Panel v2 字段差异 | 探测字段缺失 | P1 宽松 DTO；P2 用真实节点校准 |

## 16. 实施记录（P2，2026-11-16）

- 完成内容：OIDC 登录/登出（Pocket ID，Authorization Code + PKCE）、白名单/角色预留、SQLite + EF Core 初始迁移、DataProtection 加密 API Key、节点 CRUD + 分组、保存前/已保存连接测试、后台健康巡检、Blazor 页面骨架（总览/节点/审计/设置/登录跳转）、审计与错误页。
- 验证结果：`dotnet build -c Release` 0 warning 0 error；**92 个测试通过**（UnitTests 64 + ContractTests 16 + IntegrationTests 12）。冒烟：`/healthz`、`/readyz`、`/login` 均 200；数据库迁移成功；OIDC 已连通 Pocket ID 的发现与 PAR 端点（无效 client 返回 `invalid_client`，真实登录已人工验收通过）。
- 依赖版本：EF Core / Sqlite / Design、OpenIdConnect、DataProtection、Mvc.Testing 均通过 `dotnet add package --version 10.0.15` 添加。NuGet 默认解析到 11.0.0（仅支持 net11），与 net10.0 不兼容，故显式指定 10.0.x；这是对“命令安装、不手写版本”规则的例外，已在 docs/02 记录。
- 与设计偏差：
  1. 集成测试使用 Test 认证方案，并通过**环境变量**在宿主启动前注入数据目录/OIDC 配置（`ConfigureAppConfiguration` 对 Program 早期读取太晚）；
  2. OIDC 真实登录保留人工验收（自动化不依赖 Pocket ID）；
  3. Pocket ID 当前使用 PAR（Pushed Authorization Requests），.NET 10 OpenID Connect 处理器原生支持；无效 client 在 challenge 阶段返回 500，已通过 `UseExceptionHandler("/error")` 转为友好错误页。
- 部署注意：你确认的回调 `http://127.0.0.1:5188/sso/OIDC/Callback` 与“内网 IP + 反向代理 HTTPS”部署不一致。上线前需在 Pocket ID 注册外部回调（如 `https://<域名>/sso/OIDC/Callback`），并通过 `Oidc:RedirectUri` 显式配置同一地址；同时开启 `PanelFleet:ForwardedHeaders:Enabled=true`。
- 真实节点验收：已用 `http://198.51.100.10:1000`（1Panel v2.3.2）验证 Online、HMAC-SHA256、版本探测；期间发现并修复：
  1. 节点地址误填安全入口（`/myentrance`）导致 API 返回 HTML，客户端现在识别 HTML 响应并提示使用 API 根地址；
  2. 版本改从 `POST /api/v2/settings/search` 的 `systemVersion` 获取（`dashboard/base/os` 不含版本）；
  3. 首次鉴权成功未标记 `AuthState.Resolved` 的问题已修复，检测到的鉴权方式/时钟偏差可正确回写；
  4. 新增 `Nodes.SecurityEntrance` 字段与迁移（可选，单路径段），用于保存 1Panel 安全入口，仅备用：不参与 API 路径，后续可用于「打开面板 UI」跳转。
- 已知限制：真实 1Panel 节点的 `ioOption/netOption` 与字段需在 P3/P4 用真实面板校准；P2 连接测试仅验证 `dashboard/base/os` 与版本。
