# ADR-0003 用户认证仅支持 OIDC，不提供本地账号密码

- 状态：提议（P0）
- 日期：2026-11-15
- 关联：[架构设计](../01-架构设计.md)

## 背景

工具面向内网/企业运维场景，用户要求统一身份：只能对接 OIDC，不提供账号密码登录。

## 选项

A. 本地账号密码（ASP.NET Identity）；
B. 本地账号 + OIDC 双通道；
C. 仅 OIDC（Authorization Code + PKCE，confidential client）。

## 决定

采用 **仅 OIDC**。不建用户表，不提供登录表单、注册、找回密码。**授权交给 Pocket ID**：谁可以访问该客户端、用户属于哪些组由 IdP 管理；应用默认不维护邮箱白名单，可选白名单作为第二道防线。P2 通过 `groups` claim 映射管理员（`AdminRoles` 为空时所有已认证用户为管理员），只读角色预留。

## 后果

- 优点：无本地口令存储与撞库风险；身份由企业 IdP 统一治理；审计主体清晰。
- 代价：IdP 不可用时无法登录（接受，不设本地后门）；首次部署必须正确配置 IdP 与回调地址；无 IdP 时无法演示（需确认是否提供 Development 假 OIDC）。
- 首版所有白名单用户为管理员；多角色 RBAC 留待后续 ADR。
