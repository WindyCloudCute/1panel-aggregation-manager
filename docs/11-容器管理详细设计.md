# 11 P6 容器管理详细设计

- 版本：v1.0
- 状态：**实施中（P6）**
- 关联：[需求与范围](00-需求与范围.md) / [架构设计](01-架构设计.md) / [工作约束](02-工作约束.md) / [P4 设计](07-P4-只读资源清单详细设计.md) / [P5 写操作内核](09-P5-写操作内核详细设计.md) / [功能扩展路线图](08-功能扩展路线图.md)
- 真实探测时间：2026-11-16（1Panel **v2.3.2**，真实节点地址与 API Key 在本文中省略）

## 1. 目标与范围

在 P5 写操作内核（`docs/09`）之上实现容器管理：

1. **列表增强**：多节点聚合容器列表，状态/端口/镜像/来源（应用 / Compose / 手动）/关联网站/固定标记/实时 CPU 与内存；
2. **行内操作**：启动、停止、重启、暂停、恢复、删除（删除按 High 风险强确认；批量 Critical）；
3. **inspect 详情**：Docker inspect 字段展平 + 容器 Config 汇总 + 容器层/镜像层磁盘占用；
4. **资源统计**：实时 CPU/内存/IO/网络（P6 展示快照，不做历史曲线）；
5. **日志 tail**：一次性读取容器日志快照（tail/since/时间戳），**非流式**（流式日志留给 P10）；
6. **Compose 项目**：聚合项目列表（运行数/容器明细/Compose 文件路径），启动/停止/重启/移除；
7. **批量操作**：复用内核的"逐节点顺序执行 + 失败即停止 + 逐节点审计 + 批次审计"，批量风险 Critical；
8. **终端**：容器详情/行内提供「打开终端」链接 `/terminal?nodeId=<id>&container=<name>`，终端能力由 P11 提供，P6 **不实现** WebSocket。

### 非目标

- 容器创建 / 编辑 / 升级镜像 / commit / 文件浏览 / 网络 / 卷 / 镜像仓库管理（1Panel 有接口，P6 不做）；
- 容器 prune（清理）与日志清理（`containers/prune`、`containers/clean/log`）——高危且不在范围；
- 容器 exec 终端与实时日志流（P11 / P10）；
- 多节点容器编排、跨节点迁移。

## 2. 真实接口探测结论（1Panel v2.3.2）

### 2.1 探测方法

使用仓库内只读探测工具（API Key 仅通过命令行环境变量传入，不落盘）：

```powershell
$env:PANELFLEET_PROBE_URL='http://<节点地址>:1000'
$env:PANELFLEET_PROBE_KEY='<API Key>'
python tools/probe/panel_probe.py POST api/v2/containers/search '{"page":1,"pageSize":20,"state":"all","orderBy":"createdAt","order":"descending"}'
```

真实节点上**只执行只读探测**（列表/详情/inspect/统计/日志/Compose 列表/镜像列表），未执行任何容器写操作。
节点版本由 `POST api/v2/settings/search` 返回：`systemVersion = "v2.3.2"`。

### 2.2 容器接口表（实测）

| 方法 | 路径 | 用途 | 请求（实测字段） | 响应 |
|---|---|---|---|---|
| POST | `api/v2/containers/search` | 容器分页列表 | `page`、`pageSize`、`name`、`state`、`filters`、`orderBy`、`order`、`excludeAppStore`；`state` 必填 `all/created/running/paused/restarting/removing/exited/dead`，`orderBy` 必填 `name/createdAt/state`，`order` 必填 `null/ascending/descending` | `{total, items:[ContainerInfo]}`；实测 8 个容器 |
| POST | `api/v2/containers/info` | 容器配置汇总 | `{name}`（必填） | `{name,image,hostname,domainName,dns[],networks[],ports[],volumes[],env[],labels[],restartPolicy,workingDir,cmd[],entrypoint[],cpuShares,memory,...}` |
| POST | `api/v2/containers/inspect` | Docker inspect | `{id, type:"container", detail:""}`；`ID`、`Type` 必填 | `data` 为 **JSON 字符串**（Docker inspect 原始 JSON），含 `Id/Name/State/Config/HostConfig/Mounts/NetworkSettings` |
| POST | `api/v2/containers/operate` | 批量容器操作（**异步任务**） | `{taskID, names:[], operation}`；`names`、`operation` 必填，`operation ∈ up/start/stop/restart/kill/pause/unpause/remove` | 立即返回 `code=200`，实际执行在 1Panel 后台任务（`taskID` 可查任务日志） |
| POST | `api/v2/containers/rename` | 重命名（同步） | `{name,newName}` | `code=200`；目标名已存在时返回业务错误 |
| GET | `api/v2/containers/status` | 容器/镜像/网络等数量汇总 | 无 | `{created,running,paused,restarting,removing,exited,dead,containerCount,composeCount,imageCount,...}` |
| GET | `api/v2/containers/list/stats` | 批量实时统计（列表页 CPU/内存） | 无 | `[{containerID,cpuTotalUsage,systemUsage,cpuPercent,percpuUsage,memoryCache,memoryUsage,memoryLimit,memoryPercent}]` |
| GET | `api/v2/containers/stats/{id}` | 单容器实时统计 | 路径参数为容器 ID 或名称 | `{cpuPercent,memory,cache,ioRead,ioWrite,networkRX,networkTX,shotTime}` |
| POST | `api/v2/containers/item/stats` | 单容器磁盘占用 | `{name}` | `{sizeRw,sizeRootFs,containerUsage,...}` |
| GET | `api/v2/containers/search/log` | 容器/Compose 日志 **SSE** | `container` 或 `compose`、`since`、`tail`、`follow`、`timestamp`；**必须** `Accept: text/event-stream` | `text/event-stream`；每行 `data: <日志行>`，结束时流关闭；错误为 `event: error\ndata: <message>` |
| POST | `api/v2/containers/compose/search` | Compose 项目分页 | `info`、`page`、`pageSize`、`excludeAppStore` | `{total, items:[ComposeInfo]}` |
| POST | `api/v2/containers/compose/operate` | Compose 操作（同步） | `{name,path,operation,withFile,force}`；`name`、`operation` 必填，`operation ∈ up/start/restart/stop/down/delete/rebuild` | `code=200`，命令执行完成后返回 |
| POST | `api/v2/containers/image/search` | 镜像分页 | `page,pageSize,name,orderBy,order`（后两者必填） | `{total, items:[{id,createdAt,isUsed,tags[],size,isPinned,description}]}` |
| GET | `api/v2/containers/image/all` | 全部镜像 | 无 | 同上数组 |
| POST | `api/v2/containers/prune` | 清理容器/镜像/卷/网络/构建缓存（**P6 不做**） | `{pruneType,withTagAll}` | `code=200` |

## 3. 设计

### 3.1 写操作清单（内核 Kind / 风险）

批量定义：**目标节点数 > 1 或 容器数 > 1** 即视为批量，风险提升为 **Critical**（与任务要求"批量 Critical"一致）；单目标风险如下：

| Kind | 1Panel operation | 单目标风险 | 批量 | 说明 |
|---|---|---|---|---|
| `container.start` | `start` | Medium | Critical | 已停止容器启动 |
| `container.stop` | `stop` | Medium | Critical | 停止运行容器 |
| `container.restart` | `restart` | Medium | Critical | 重启 |
| `container.pause` | `pause` | Medium | Critical | 暂停 |
| `container.unpause` | `unpause` | Medium | Critical | 恢复 |
| `container.delete` | `remove` | **High** | **Critical** | 强确认；同时删除匿名卷，不可恢复 |
| `container.rename` | 独立 `containers/rename` | **High** | 拒绝批量 | 改名影响网站/应用/脚本引用；Compose 容器可能失效 |
| `compose.up` | `up` | Medium | Critical | 启动项目（`docker compose up`） |
| `compose.stop` | `stop` | Medium | Critical | 停止项目容器 |
| `compose.restart` | `restart` | Medium | Critical | 重启项目 |
| `compose.down` | `down` | **High** | Critical | 停止并移除项目容器/网络（无自动回滚） |

约束：

- 单次批量最多 **20 个容器**（`ContainerOptions.MaxBatchContainers`），避免误选整页；批量上限超过后预览直接拒绝；
- 批量仍受内核 `Operations:MaxBatchNodes`（默认 50）约束；
- 内核按节点**顺序**执行，任一节点失败即停止后续节点，已执行节点不回滚；
- 每个节点执行前获取节点写锁（内核 `OperationGuards`），拿不到锁则停止批次；
- 预览中展示节点数、容器清单摘要与警告；Critical 额外要求输入确认文本（处理器覆盖为如 `确认停止2个节点共2个容器` / `确认移除1个节点的Compose项目`）。

#### 参数契约（写操作 JSON）

单容器（行内操作）：

```json
{ "container": "web", "source": "手动" }
```

批量（同一次操作跨节点，每个节点各自的容器清单）：

```json
{
  "containersByNode": {
    "<nodeId-N>": ["web", "worker"],
    "<nodeId-N2>": ["cache"]
  },
  "source": "批量"
}
```

- 节点 id 使用 `Guid.ToString("N")`；参数中出现的节点必须都在 `nodeIds` 中，否则预览拒绝（防止 UI 参数错位）；
- 容器名按 Docker 规则校验：`^[A-Za-z0-9][A-Za-z0-9_.-]{0,127}$`（同时阻断命令注入字符）；
- `source` 仅用于预览警告（应用/Compose 管理的容器会有额外提示），不参与请求。

Compose：

```json
{ "compose": "webstack", "path": "/opt/1panel/docker/compose/webstack/docker-compose.yml", "source": "Compose" }
```

- `path` 来自 `compose/search` 的 `path`，逐节点不同；批量 Compose 时内核只接受**同一路径**跨节点，UI 当前只允许单节点操作；
- 路径长度 ≤ 4096、禁止控制字符与 `&& ; | \` $(` 等注入字符（1Panel 服务端另有 CheckIllegal）。

重命名：`{ "container": "web", "newName": "web-2" }`（单节点）。

#### 执行语义与确认

1. 内核 `PreviewAsync` → `OperationConfirmDialog`；
2. 确认后内核逐节点调用 `containers/operate`（单次提交该节点全部容器名），返回 `TaskId`；
3. 提交成功后**尽力确认状态**：在 `ContainerOptions.VerifyTimeoutSeconds`（默认 3s）内轮询 `containers/inspect`：
   - 启动/重启/恢复 → 期望 `running`；停止 → `exited`；暂停 → `paused`；
   - 删除 → inspect 报"不存在"即确认已删除；
   - 超时只提示"已提交 1Panel 异步任务，未在 N 秒内确认状态"，不判定失败（1Panel 为异步任务，见 §8 风险）；
4. 结果通过 `OperationResultView` 展示，逐节点成功/失败/消息/`taskID`/耗时；执行后自动刷新列表；
5. 删除确认文本默认由内核按风险计算（单节点=节点名）；批量与 Critical 使用处理器覆盖文本。

### 3.2 只读服务（`IContainerService`）

| 方法 | 说明 |
|---|---|
| `ListAsync(ContainerQuery query)` | 逐节点并发拉取 `containers/search` + `containers/list/stats`；按节点隔离失败；合并后过滤/排序/分页 |
| `GetDetailAsync(nodeId, containerName)` | 并行 `containers/info` + `containers/inspect`，展平字典；再尽力读取 stats/itemStats |
| `GetStatsAsync(nodeId, name, containerId?)` | `GET containers/stats/{id}` + `POST containers/item/stats` |
| `GetLogsAsync(nodeId, ContainerLogRequest)` | 通过 `IContainerLogClient` 读取 SSE 日志（follow=false，一次性快照） |
| `ListComposeAsync(query)` | 逐节点 `containers/compose/search`，聚合项目与容器明细 |

聚合语义：

- 并发上限 `MaxConcurrency`（默认 6），单节点超时 `NodeTimeoutSeconds`（默认 10s）；
- 单节点失败不阻断其它节点：该节点标记 `Failed` + `PanelError`，页面顶部节点状态条展示；
- 每节点最多拉取 `PerNodePageSize`（默认 200）条；合并排序后按 `PageSize` 客户端分页，`TotalMatched = Σ 各节点 total`；
- 禁用节点不参与只读查询（直接详情返回 404）。

### 3.3 Client 层

- `ContainerRoutes`：容器/Compose/镜像/日志路由与 `ContainerLog(...)` SSE 参数拼装（唯一路由定义处）；
- `Dto/Containers/ContainerDtos.cs`：宽松解析 DTO（缺失/类型变化不抛）；请求记录（Search/Operate/Rename/Inspect/Compose/Image）；
- `ContainerLogClient.cs`：SSE 日志域客户端（见 §3.6）。

### 3.4 Application 层

- `Containers/ContainerService.cs`：只读聚合服务；
- `Containers/ContainerOperationHandlers.cs`：11 个 `IOperationHandler`（容器 7 + Compose 4）；
- `Containers/ContainerModels.cs` / `ContainerOptions.cs` / `SecretMasker.cs`；
- `Containers/ContainerModule.cs`：`AddContainerModule(this IServiceCollection)`（幂等，重复调用直接返回）。

### 3.5 安全设计

1. **Compose env 永不出域**：`ComposeItemDto` 不映射 `env`、不使用扩展数据；API/页面只输出项目名/路径/运行数/容器明细；
2. **inspect env 脱敏**：`Config.Env` 在 `FlattenInspect` 中逐条经 `SecretMasker.MaskEntry`；敏感键名（PASSWORD/PASSWD/PWD/SECRET/TOKEN/KEY/CREDENTIAL/AUTH 等）值替换为 `***`；
3. **日志内容不落审计**：日志只读返回页面，审计只记录操作元数据（`kind`、节点、容器数、目标 id、结果），参数只记录键名；
4. **API Key**：只经 `INodeSecretProtector` 在 Infrastructure 内解密，日志/文档/异常不含 Key；本设计文档不含节点地址与 Key；
5. **危险操作**：删除/Compose down 强确认（High）、批量 Critical；无自动重试/自动回滚；
6. **终端**：P6 只生成链接，不在本模块建立任何 WebSocket 或执行命令。

### 3.6 日志读取（SSE 域客户端）

`IContainerLogClient.ReadAsync(ContainerLogQuery, CancellationToken)`：

- 请求：`GET /api/v2/containers/search/log?container=...&since=...&tail=...&follow=false&timestamp=...`，`Accept: text/event-stream`，签名头复用程序集内 `ApiKeySigningHandler`；
- 鉴权失败处理与 `PanelClient` 一致：401 时按 `Date` 头校正时钟重试一次，`Auto` 模式回退 MD5；
- 限制：单次最多 **2000 行 / 1 MiB / 单行 8192 字符**，读取预算 15s；`tail` 夹取 1..2000（页面选项 100/200/500/1000）；
- 解析 `data:` 行；`event: error` 转为 `PanelError`；流结束即返回；
- **follow=false**：不建立长连接、不做实时跟随（流式日志由 P10 实现）；
- 日志行不做持久化、不写审计。

## 12. P20 Compose 增删改（v2 增补，task-30）

### 12.1 接口契约（以 `docs/research/p20-api-routes.md` §3 为准）

| 用途 | 方法 + 路径 | 请求体 | 返回/语义 |
|---|---|---|---|
| 项目列表 | `POST api/v2/containers/compose/search` | `{page,pageSize,info?,excludeAppStore?}` | `ComposeInfo[]`（含 `configFile`、`workdir`、`path`、`composeFileExists`） |
| 创建（校验） | `POST api/v2/containers/compose/test` | 同创建 | `bool`，仅校验不落盘 |
| 创建/启动 | `POST api/v2/containers/compose` | `ComposeCreate{taskID,name?,dirName?,from,file,path?,env?,forcePull?}` | 提交后台任务；HTTP 成功 ≠ 创建完成 |
| 编辑 | `POST api/v2/containers/compose/update` | `ComposeUpdate{taskID,name,path,detailPath,content,env?,forcePull?}` | 提交后台任务；`detailPath` 必须显式传（服务端据此读旧文件做失败回滚） |
| 启停/下线/重建/删除 | `POST api/v2/containers/compose/operate` | `ComposeOperation{name,path?,operation,withFile?,force?}` | 同步；`rebuild` = down + up |
| 读取 `.env` | `POST api/v2/containers/compose/env` | `{path}` | `.env` 文本 |
| 读取 YAML 内容 | `POST api/v2/files/content` | `{path,isDetail:false}` | `data` 为扁平 FileInfo：`content/size/path/name/mimeType/extension/isDir` |

关键语义与限制：

- 创建/编辑为 1Panel 后台任务（`taskID` 由客户端生成，32 位 hex），面板只表示“已受理”；P20 不做任务轮询，结果以刷新列表/容器状态为准，提示中不承诺成功。
- 删除为同步；`withFile=true` 会同时删除整个 Compose 项目目录（Critical）；`force=true` 忽略 down 失败；匿名卷等由 1Panel 语义决定。
- `files/content` 无目录 jail：超过 10MB 返回 HTTP 200 + `code:500`（`File is larger than 10 MB`），二进制返回 `File preview is not supported`，不存在返回 `The target path does not exist!`；2KB–5MB 可能 gzip（PanelClient 已启用自动解压）。
- Compose 列表的 `env` 为明文秘密，聚合 DTO 不映射、不落库、不进日志。

### 12.2 Application 层

- 只读：`IComposeContentService.GetComposeContentAsync(nodeId, projectName)`：先 `compose/search` 精确匹配项目名，取 `configFile`（优先）或 `workdir + /docker-compose.yml`，并以 `workdir` 为根校验：路径规范化后必须位于项目目录下、文件名以 `.yml/.yaml` 结尾、不得含 `..`/控制字符；通过后调用 `files/content` 读取。
- 单文件只读上限 1MiB：超过后截断并返回 `Truncated=true`，前端提示“仅加载前 1 MiB”，允许用户手工补全；读取失败/二进制/不存在时返回可读错误，前端降级为手写 YAML。
- 新增内核处理器：

| Kind | 风险 | 参数 | 执行 |
|---|---|---|---|
| `compose.create` | 单节点 High / 批量 Critical | `compose`(小写项目名)、`content`(≤256KiB)、`env?`、`forcePull?` | 生成 taskID 后 POST 创建，回填 `TaskId` |
| `compose.update` | 单节点 High / 批量 Critical | `compose`、`path`、`content`、`detailPath?`、`env?`、`forcePull?` | 生成 taskID 后 POST 更新，回填 `TaskId` |
| `compose.rebuild` | High | `compose`、`path` | POST operate `rebuild`（同步） |
| `compose.delete` | Critical（始终） | `compose`、`path?`、`withFile?`、`force?` | 强确认文本 = 项目名；POST operate `delete` |

- 校验：创建名 `^[a-z0-9][a-z0-9_-]{0,255}$`；内容非空、≤256KiB、无 NUL；路径必须绝对且拒绝 shell 注入字符（`&&`、`;`、`|`、反引号、`$(`）与 `..`；`detailPath` 必须位于项目目录下。
- 审计：只记录 kind/节点/项目名/是否 withFile/force 等参数键，**绝不记录 YAML 与 .env 内容**；失败信息只含 1Panel 错误消息。

### 12.6 风险与部署注意

| 风险/限制 | 说明 | 缓解 |
|---|---|---|
| 创建/编辑为异步受理 | 返回成功不代表容器已启动；后台失败只体现在任务日志 | UI 明示“已提交，请刷新列表”；后续可接任务日志轮询 |
| 无任务日志回显 | 未透出 1Panel taskID 日志页面 | 文档记录；需要时增加任务查询 |
| YAML 读取依赖 `files/content` | 该接口无目录 jail，且 >10MB/二进制不可读 | 服务端只读单文件 + 项目目录/后缀校验 + 1MiB 截断 + 手写降级 |
| 编辑失败回滚 | 1Panel 会尝试用旧文件回滚，但不保证业务可用 | 不承诺回滚成功；提示以实际状态为准 |
| 删除 withFile | 直接删除项目目录与容器，不可撤销 | Critical + 输入项目名确认 + UI 单独勾选 |
| 内容进入审计风险 | 若把 YAML 放参数会入库 | handler 只读 content 用于请求，审计只记录参数键/摘要 |
