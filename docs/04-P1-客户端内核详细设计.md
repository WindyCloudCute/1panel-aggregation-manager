## 7. 签名与时钟校准（核心）

### 7.1 签名

```csharp
// 时间由 TimeProvider 提供，便于测试
long ts = _timeProvider.GetUtcNow().ToUnixTimeSeconds();
string timestamp = ts.ToString(CultureInfo.InvariantCulture);

if (mode == AuthMode.HmacSha256)
{
    byte[] mac = HMACSHA256.HashData(Encoding.UTF8.GetBytes(apiKey), Encoding.UTF8.GetBytes("1panel:" + timestamp));
    token = Convert.ToHexStringLower(mac);
}
else // Md5
{
    byte[] hash = MD5.HashData(Encoding.UTF8.GetBytes("1panel" + apiKey + timestamp));
    token = Convert.ToHexStringLower(hash);
}

request.Headers.TryAddWithoutValidation("1Panel-Timestamp", timestamp);
request.Headers.TryAddWithoutValidation("1Panel-Token", token);
```

- 十六进制小写（与服务端 `hex.EncodeToString` 一致）。
- `Auto` 默认 HMAC；HMAC 鉴权失败时回退 MD5（仅 401 且模式为 Auto）。
- 禁止把 token / API Key 写入日志。

### 7.2 时钟偏差流程

```
请求 1（HMAC，timestamp = now + offset[0]）
  ├ 成功 → 记录 AuthMode=HmacSha256、offset
  └ 401
       offset = response.Date - UtcNow（Date 头存在才有效）
       请求 2（纠正 timestamp，同一模式）
         ├ 成功 → 持久化 offset（P2 写入节点记录）
         └ 401 且 Auto → 请求 3（MD5 + 纠正 timestamp）
              ├ 成功 → 记住 MD5
              └ 失败 → Unauthorized（诊断：时钟偏差约 N 秒 / 鉴权方式不匹配 / Key 或白名单问题）
```

- 最多 3 次网络请求；其余情况不重试。
- 无 `Date` 头时跳过校准直接回退鉴权方式。
- 偏差记录只在内存（P1），P2 持久化到节点。

### 7.3 超时

- 单次调用预算默认 8s；由 `CancellationTokenSource.CreateLinkedTokenSource(ct)` + `CancelAfter` 实现。
- 区分：用户取消 → `Canceled`；预算耗尽 → `Timeout`。

### 7.4 HTTP 管道

- `SocketsHttpHandler`：`AllowAutoRedirect=false`、`AutomaticDecompression=GZip|Deflate|Brotli`、`ConnectTimeout=5s`、`PooledConnectionLifetime=5m`、`MaxConnectionsPerServer=4`。
- TLS：`TlsPolicy.Strict` 使用默认校验；`AllowSelfSigned` 时设置 `RemoteCertificateValidationCallback` 接受任意证书（仅该节点，且在连接测试结果中显式标注）。
- `BaseUri` 可带子路径：`PanelEndpoint.Combine("https://host/panel", "api/v2/dashboard/base/os") → https://host/panel/api/v2/...`；拼接时保留 query，禁止双斜杠。
- 3xx 不跟随，映射为 `Protocol`（提示检查反向代理/入口）。

## 8. 信封与错误映射

### 8.1 信封

```csharp
internal sealed record PanelEnvelope<T>
{
    public int Code { get; init; }
    public string? Message { get; init; }
    public string? ErrorCode { get; init; }
    public T? Data { get; init; }
}
```

- `JsonSerializerOptions`：`PropertyNameCaseInsensitive=true`、`PropertyNamingPolicy=null`、未知字段忽略、`ReadCommentHandling=Skip`。
- 响应体为空且 HTTP 200 → 视为成功、`Data=null`（`Success` 无数据场景）。
- 非 JSON / 无法解析 → `Protocol`（记录截断后的前 200 字符用于诊断，但绝不包含密钥；响应体本身不含请求密钥，安全）。

### 8.2 错误矩阵

| 场景 | 判定依据 | PanelErrorKind | 用户提示（中文） |
|---|---|---|---|
| 业务成功 | HTTP 2xx + `code=200` | — | — |
| 鉴权失败 | HTTP 401 或 `code=401` | Unauthorized | API Key 错误、时间不同步或 IP 不在白名单 |
| 无权限 | HTTP 403 或 `code=403` | Forbidden | 面板拒绝访问（检查 IP 白名单） |
| 路径不存在 | HTTP 404 | NotFound | 接口不存在，可能 1Panel 版本不兼容 |
| 参数错误 | `code=400` | Validation | 请求参数不合法 |
| 面板内部错误 | `code>=500` 或 HTTP 5xx | PanelServerError | 1Panel 内部错误（附 message） |
| 非 JSON/信封缺失 | 解析失败 | Protocol | 返回格式异常（检查反向代理/入口路径） |
| 重定向 | HTTP 3xx | Protocol | 不应出现重定向（检查 BaseUrl 与代理） |
| DNS/连接失败 | Socket/HttpRequestException | Network | 无法连接节点（网络/端口/防火墙） |
| 证书失败 | AuthenticationException | Tls | TLS 证书校验失败（自签请开启 AllowSelfSigned） |
| 超时 | 预算耗尽 | Timeout | 节点响应超时 |
| 用户取消 | 外部 token 取消 | Canceled | 已取消 |

- 映射优先级：传输异常 → HTTP 状态 → 信封解析 → `code`。
- `PanelError.Message` 保留面板原始 message（可能为空），UI 展示时叠加中文提示与诊断建议。

## 11. 假 1Panel 服务与测试清单

**FakePanelServer**：进程内 Kestrel（回环随机端口，走真实 HTTP 管线，可验证 gzip），实现最小 v2 契约，可配置：

- 校验 `1Panel-Token` / `1Panel-Timestamp`（HMAC 或 MD5），失败返回 401；
- 可选：首次鉴权失败（模拟时钟偏差）、只接受 MD5、业务错误 `code=500`、gzip、延迟 N 秒、重定向、非 JSON 响应；
- 记录收到的请求头、请求数、时间戳，供断言。

**测试用例**（必须全部通过）：

| 编号 | 用例 | 断言 |
|---|---|---|
| CT-01 | HMAC 签名正确 | 服务端验证通过；请求头存在且 timestamp 合理 |

1. `base/os` 与 `current/node` 的返回字段在不同 v2 小版本可能不同 → 宽松 DTO + 能力探测，P2 用真实节点校准；

5. 网络受限环境下无法下载 MinGit → 需你提供安装包或批准提权安装。
