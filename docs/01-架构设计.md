- 关联：[需求与范围](00-需求与范围.md) / [工作约束](02-工作约束.md) / [阶段计划](03-阶段计划.md)

## 1. 架构原则

1. **Agentless**：只通过 1Panel 自身 API 接入，不向目标机部署任何程序；目标机只需放行 IP。
2. **部分失败优先**：任何一屏数据都由 N 个节点结果的集合构成；单节点失败不能拖垮整页。
3. **显式降级**：慢、超时、不可达、鉴权失败都在 UI 明确标注；缓存数据带时间戳，不冒充实时。
4. **秘密最小暴露**：API Key 只进不出；日志、异常、API 响应、页面 DOM 中不得出现明文。
5. **契约可回归**：用假 1Panel 服务固定鉴权与响应契约，测试不依赖真实面板。
6. **单进程交付**：一个 ASP.NET Core 进程包含 UI、API、后台巡检与 SQLite，P5 再做服务化/容器化。

## 4. 1Panel v2 接入契约（已核实的事实）

来源：[1Panel v2 API 文档](https://1panel.pro/docs/v2/dev_manual/api_manual/)、1Panel 源码（`agent/init/router/router.go`、`agent/app/api/v2/helper/helper.go`）。

### 4.1 基础

- 节点地址：`http(s)://host:port`，可带反向代理子路径（如 `https://host/panel`），API 以 `/api/v2/...` 拼接。
- API 前缀：`/api/v2`（源码 `Router.Group("/api/v2")`）。
- 响应统一信封：`{ "code": int, "message": string, "data": any, "errorCode": string? }`。
- **业务错误仍返回 HTTP 200**，必须以 `code` 判断成败；HTTP 状态码仅用于传输层与鉴权中间件。
- 部分端点返回 **gzip**（`Content-Encoding: gzip`），客户端必须开启自动解压。

### 4.2 鉴权（两种签名，服务端均兼容）

请求头：

| Header | 值 |
|---|---|
| `1Panel-Timestamp` | 当前 Unix 秒级时间戳 |
| `1Panel-Token` | 见下 |

- 推荐 HMAC-SHA256：`hex( HMAC_SHA256(key=APIKey, data="1panel:"+timestamp) )`
- 兼容 MD5（旧版本）：`hex( MD5("1panel" + APIKey + timestamp) )`
- 时间戳偏差会导致 401（服务端返回「API 接口密钥错误」），需 NTP 或客户端校准。

### 4.3 错误与状态

- 鉴权失败：HTTP 401（中间件层）。
- 业务错误：HTTP 200 + `code` 非 200（如 400 参数错误、500 内部错误）。
- 可能返回重定向（反向代理/入口页），客户端不得跟随，按协议错误处理。

### 4.4 P1 使用的最小端点（核实自源码）

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/api/v2/dashboard/base/os` | OS 信息（鉴权探针首选） |
| GET | `/api/v2/dashboard/current/node` | 节点当前指标 |
| GET | `/api/v2/dashboard/base/{ioOption}/{netOption}` | 面板基础信息 + 当前指标；首版传 `all/all` |
| GET | `/api/v2/dashboard/current/{ioOption}/{netOption}` | 当前指标；首版传 `all/all` |

> 其余清单端点（websites/apps/containers/databases/cronjobs 的 search）在 P4 设计阶段用真实面板 swagger 或源码逐条核实后写入路由常量。

## 5. 客户端设计（PanelFleet.Client）

### 5.1 处理管道

```
PanelClient.SendAsync
  → 路由常量拼 URL（BaseUri + RelativePath）
  → ApiKeySigningHandler（签名、时间戳、时钟校准重试、鉴权模式回退）
  → 韧性策略（超时、GET 重试、熔断）
  → SocketsHttpHandler（连接池、自动解压、证书校验策略、禁跟随重定向）
  → 响应读取
  → EnvelopeDecoder（code/message/data）
  → PanelErrorMapper（异常/错误 → PanelErrorKind）
```

### 5.2 签名与时钟校准

- 每节点状态：`AuthMode`（Auto/HmacSha256/Md5）、`ClockOffset`（TimeSpan）。
- 请求时间戳 = `UtcNow + ClockOffset`；Auto 模式先 HMAC。
- 收到 401 时：读取响应 `Date` 头，计算 `offset = Date - UtcNow`；用修正时间戳重试 **一次**；成功则记住 offset 与鉴权模式。
- 若 HMAC 仍 401 且模式为 Auto：改用 MD5 重试一次；成功则缓存该节点使用 MD5。
- 两次都失败 → `Unauthorized`，诊断信息包含「时间偏差约 N 秒 / 鉴权方式不匹配」等可操作提示（不含密钥）。

### 5.3 错误分类

```csharp
public enum PanelErrorKind
{
    Unauthorized,     // 401 / code 401：API Key 错误、时间偏差、白名单
    Forbidden,        // 403：IP 不在白名单等
    NotFound,         // 404：路径不存在/版本不支持
    Unsupported,      // 能力探测确认端点不存在
    Validation,       // code 400：参数错误
    PanelServerError, // code 5xx：面板内部错误
    Protocol,         // 非 JSON、信封缺失、重定向、非预期内容
    Network,          // DNS/连接失败/连接重置
    Tls,              // 证书校验失败
    Timeout,
    Canceled          // 用户主动取消
}
```

### 5.4 节点级结果

```csharp
public enum NodeResultStatus { Ok, Stale, Failed, Unsupported }

public sealed record NodeResult<T>(
    NodeId NodeId,
    NodeResultStatus Status,
    T? Data,
    PanelError? Error,
    TimeSpan Elapsed,
    DateTimeOffset? CachedAt);
```

- `Ok`：本次成功；
- `Stale`：本次失败，返回 TTL 内的最近快照（`CachedAt` 标注）；
- `Failed`：失败且无可用快照；
- `Unsupported`：该节点/版本不具备此能力。

### 5.5 能力探测

- 连接测试时调用 `GET /api/v2/dashboard/base/os`，记录：HTTP 延迟、`code`、面板版本（若响应含版本/OS 信息）、鉴权模式、时钟偏差。
- 能力标志（首版）：`Dashboard`、`Websites`、`Apps`、`Containers`、`Databases`、`Cronjobs`；探测失败仅影响对应模块入口（禁用并提示原因）。

### 5.6 TLS

- 每节点 `TlsPolicy`：`Strict`（默认，校验证书与主机名）或 `AllowSelfSigned`（接受任意证书，UI 明确风险提示）。
- 不允许全局关闭证书校验。

## 6. 聚合与缓存

### 6.1 总览 Fan-out

- 全局并发上限 8；每节点并发 2；单节点超时 8s；总览请求预算 12s。
- 只对幂等 GET 做 1 次瞬时错误重试；超时/取消不重试。
- 每节点独立熔断（连续失败 3 次或失败率 > 50% 且样本 ≥ 5 → 打开 30s）。
- 结果通过 SignalR 逐节点推送，前端卡片独立更新；最后补一个汇总帧（在线/降级/离线计数）。
- 失败节点优先返回 ≤ 5 分钟的最近快照并标 `Stale`；无快照显示错误原因与「重试」。

### 6.2 资源清单（P4）

- 每节点按 `page=1, pageSize=N`（默认 N=100，可配，上限 200）拉取，服务端合并、过滤、排序。
- 不提供虚假的全局总数：显示「已加载 per-node N 条上限」提示；单节点继续翻页由节点列的“加载更多”触发（P4 再细化）。
- 过滤条件尽量下推到节点；无法下推的条件在合并后本地过滤，并在 UI 说明。

## 7. 数据模型（SQLite / EF Core）

```
Node
  Id(Guid)  Name  BaseUrl  SecurityEntrance?  ApiKeyProtected  ApiKeyHint  AuthMode
  TlsPolicy  GroupId?  Tags(json)  Remark
  PanelVersion?  Capabilities(int flags)  ClockOffsetTicks?
  HealthStatus  HealthMessage  LastCheckedAt  LastSeenAt
  CreatedAt  UpdatedAt

NodeGroup        Id, Name, SortOrder
AuditEvent       Id, OccurredAt, ActorSubject, ActorName, Action,
                 TargetType, TargetId, NodeId?, DetailJson, ClientIp, TraceId
AppSetting       Key, Value
```

- `ApiKeyProtected` 使用 ASP.NET DataProtection（purpose：`PanelFleet.NodeApiKeys`）加密；页面只显示 `ApiKeyHint`（末 4 位）。
- DataProtection 密钥持久化到数据目录 `keys/`（Windows 下用 DPAPI 保护）；数据目录默认 `%ProgramData%\PanelFleet`，可用 `PANELFLEET_DATA_DIR` 覆盖。
- 迁移使用 EF Core Migrations；每次结构变更必须附迁移与回滚说明。

## 8. 认证与授权（OIDC Only）

- **不提供本地账号密码登录**。唯一登录方式：OIDC Authorization Code + PKCE（confidential client）。
- ASP.NET Core：Cookie（默认方案）+ OpenIdConnect（challenge 方案）；`SaveTokens=false`；登出做本地 Cookie 注销 + 可选 RP-Initiated Logout。
- 当前提供方：**Pocket ID**（发现地址 `https://auth.example.com/.well-known/openid-configuration`，Authorization Code + PKCE）。
- 配置：`Oidc:Authority`、`ClientId`、`ClientSecret`（环境变量注入）、`RequireHttpsMetadata`、`Scopes`、`CallbackPath`（按 Pocket ID 配置，当前约定 `/sso/OIDC/Callback`）。
- 授权：**由 Pocket ID 负责**（客户端授权范围与用户组由 IdP 管理）；可选 `Auth:AllowedEmails` / `AllowedSubjects` 作为第二道防线（默认空）。
- 角色映射：`Oidc:RoleClaimType`（默认 `groups`）+ `Oidc:AdminRoles`；为空则所有已认证用户为管理员，非空则仅命中组为管理员；`ReadOnlyRoles` 预留。审计记录 `sub`/`email`/`name` 与组。
- Cookie：`HttpOnly`、`SameSite=Lax`、HTTPS 下 `Secure=Always`、滑动过期 8 小时、DataProtection 持久化。
- 开发/测试：自动化测试用测试认证方案；浏览器手动验收需真实 IdP，或按确认结果启用「仅本机 Development 的假 OIDC」（见开放问题）。

## 9. 安全

| 项 | 措施 |
|---|---|
| 监听地址 | 默认 `http://127.0.0.1:5188`；对外监听必须显式配置并启用 HTTPS |
| 登录 | OIDC only + 白名单，fail-closed |
| 会话 | Cookie + Antiforgery；SSE/SignalR 走同源；CSP、X-Content-Type-Options、Referrer-Policy |
| 节点密钥 | DataProtection 加密；不写日志；API 不回显；页面仅末 4 位 |
| 审计 | 登录/登出、节点增删改、连接测试、设置变更；含 actor、IP、traceId |
| 日志 | Serilog 结构化日志；`ApiKey`/`Token`/`Authorization` 字段脱敏；滚动文件保留 14 天 |
| 依赖 | 锁定版本（Directory.Packages.props），新增依赖需在设计文档列明 |

## 10. 可观测性

- `/healthz`：进程存活（匿名）。
- `/readyz`：SQLite 可写、DataProtection 可用、OIDC 配置有效（匿名，但只返回 ok/degraded）。
- 每个请求带 `TraceId`（`Activity`），日志与审计关联。
- 节点巡检结果记录为结构化日志（节点、耗时、错误分类），不打印响应体。

## 11. 测试策略

| 层级 | 内容 | 依赖 |
|---|---|---|
| 单元测试 | 签名计算、时钟校准、错误映射、缓存 TTL、合并排序、选项校验 | 无 |
| 契约测试 | 进程内假 1Panel v2（最小 API）：校验 HMAC/MD5、时间戳、信封、gzip、业务错误、超时、重定向 | 无真实面板 |
| 集成测试（可选） | 通过环境变量指向真实节点做冒烟，默认跳过 | 真实面板 |
| UI 测试 | P2 起用 bUnit 测关键组件；P5 手工验收 + Playwright（可选） | 无 |

## 12. 部署形态（首版）

- `dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`；
- 运行方式：前台运行 / Windows 服务（P5）；数据目录独立于程序目录，便于升级；
- 反向代理：支持 `ASPNETCORE_FORWARDEDHEADERS_ENABLED`，默认只监听本机；
- 首版不强制 Docker（P5 评估）。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 1Panel v2 各小版本接口差异 | 部分功能不可用 | 路由常量集中管理；能力探测；未来可解析节点 swagger 自动发现；支持矩阵写入文档 |
| 时间不同步 | 鉴权 401 | Date 头校准 + 重试 + 诊断提示 |
| API Key 全权限 | 泄露即失守 | 加密、脱敏、白名单、仅本机监听、可轮换 |
| 自签证书 | 连接失败 | 节点级 TLS 策略 + 风险提示 |
| 节点多/慢 | 页面卡死 | 并发上限、超时、熔断、快照兜底、增量渲染 |
| OIDC IdP 不可用 | 无法登录 | 明确错误页；运维保持 IdP 高可用；不提供本地后门 |
| 无 git 环境 | 无法回滚 | P1 前安装 MinGit 便携版到 `tools/`（不提交） |
