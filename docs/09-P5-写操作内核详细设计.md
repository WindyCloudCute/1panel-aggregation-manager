## 1. 目标与范围

本内核是所有写操作（应用商店、容器、网站、数据库、计划任务、1Panel 更新）的公共基础设施，提供统一流程：

**预览（Preview）→ 风险分级 → 二次确认（High/Critical 需输入确认文本）→ 执行（逐节点顺序）→ 审计（逐节点 + 批次）→ 结果展示。**

不在本内核范围：具体业务参数与 1Panel 路由（由各阶段 `IOperationHandler` 实现）、WebSocket 终端（P11）、日志流（P10）。

## 2. 核心模型

```csharp
public enum OperationRisk { Low, Medium, High, Critical }
public enum OperationStatus { Succeeded, Failed, PartiallySucceeded, Rejected }

// 调用方提交：操作类型 + 节点 + 参数（JSON）
public sealed record OperationInvocation(string Kind, IReadOnlyList<NodeId> NodeIds, JsonObject? Parameters);

// 处理器计算：展示信息 + 风险 + 目标 + 警告 + 确认文本覆盖
public sealed record OperationPlan(
    string Title, string Summary, OperationRisk Risk,
    IReadOnlyList<OperationTarget> Targets, IReadOnlyList<string> Warnings,
    string? TypedConfirmationText = null, string? TargetType = null);

// 返回前端：确认弹窗数据（含一次性 Token）
public sealed record OperationPreview(
    Guid TokenId, string Kind, string Title, string Summary, OperationRisk Risk,
    bool RequiresTypedConfirmation, string? ConfirmText,
    IReadOnlyList<OperationTarget> Targets, IReadOnlyList<string> Warnings,
    DateTimeOffset CreatedAt, DateTimeOffset ExpiresAt);

// 每节点执行结果
public sealed record OperationStepResult(
    NodeId NodeId, string NodeName, bool Success, string Message,
    string? TaskId, string? DetailJson, PanelError? Error, TimeSpan Duration,
    string? TargetId = null);

// 一次执行（单节点或批量）
public sealed record OperationExecution(
    Guid Id, string Kind, string Title, OperationRisk Risk, OperationStatus Status,
    DateTimeOffset StartedAt, DateTimeOffset FinishedAt, IReadOnlyList<OperationStepResult> Steps);
```

处理器契约：

```csharp
public interface IOperationHandler
{
    string Kind { get; }                                   // 如 "app.install"、"container.stop"
    Task<OperationPlan> PlanAsync(OperationPlanContext ctx, CancellationToken ct);   // 校验参数、生成预览
    Task<OperationStepResult> ExecuteAsync(OperationNodeContext ctx, CancellationToken ct); // 单节点执行
}
```

`PlanAsync` 拿到全部节点（用于批量警告/容量判断），`ExecuteAsync` 只拿单节点 + 已创建的 `IPanelClient`。

## 3. 状态机与安全规则

### 3.1 流程

```
Preview ──(生成一次性 token，TTL 120s，绑定操作者)──▶ 前端确认弹窗
   │
   ├─ 取消/关闭：token 过期作废，无审计
   └─ 确认 ──▶ Execute(token, typedText)
                 ├─ token 不存在/过期/他人 token        → OperationConfirmationException（审计 operation.rejected）
                 ├─ 需要强确认但文本不一致               → OperationConfirmationException（审计 operation.rejected）
                 ├─ 相同操作指纹在去重窗口（10s）内重复     → OperationConfirmationException（审计 operation.rejected）
                 └─ 通过 ──▶ 逐节点顺序执行 ──▶ 逐节点审计 + 批次审计 ──▶ 结果
```

### 3.2 风险与确认

| 风险 | 确认方式 | 典型操作 |
|---|---|---|
| Low | 一次确认（弹窗） | 查看类操作不需要写内核；启动已停止容器、创建测试库 |
| Medium | 一次确认（弹窗，显示目标与摘要） | 重启容器、修改应用配置、启停网站 |
| High | 输入确认文本（默认：单节点=节点名，批量="N 个节点"） | 删除容器、删除数据库、卸载应用 |
| Critical | 输入处理器指定文本（如 `确认删除数据库 xxx` 或 `升级 3 个节点`） | 批量删除、批量 1Panel 升级 |

规则：

- `ConfirmText` 由内核按 `RequiresTypedConfirmation = Risk >= High` 计算；处理器可用 `TypedConfirmationText` 覆盖；
- 比较前 `Trim()`，大小写敏感，必须完全相等；
- 前端在执行按钮旁始终展示风险徽标与"不可回滚"提示（High/Critical）。

### 3.3 批次语义

- 默认单节点；批量必须显式列出节点，预览里展示节点数与名称；
- **顺序执行**（一次只操作一个节点），单次上限 `MaxBatchNodes`（默认 50）；
- **失败即停止**：某节点失败后不再执行后续节点，结果状态为 `Failed`（全部失败）或 `PartiallySucceeded`（部分成功）；
- 已执行节点**不回滚**，结果逐节点展示并在审计中记录；
- 每个节点执行前获取**节点写锁**（`NodeOperationLocks`，超时 5s），拿不到锁即判定"节点正在执行其他写操作"并停止批次；
- 单节点执行超时预算 `ExecuteTimeoutSeconds`（默认 120s），处理器内部的异步轮询也受此预算约束。

### 3.4 幂等与防重

- 确认 token **一次性**，使用即失效（防双击/重放）；
- 相同操作指纹（Kind + 排序后的节点 + 参数 JSON）在 `DedupeWindowSeconds`（默认 10s）内再次执行会被拒绝并审计；
- **不做任何自动重试**：写操作失败一律交由用户重新预览确认。

### 3.5 审计

所有执行写操作必须落库（`IAuditStore`），动作命名：

| Action | 时机 | TargetType | NodeId |
|---|---|---|---|
| `operation.executed` | 单节点执行成功 | 处理器声明的 TargetType（默认 `node`） | 该节点 |
| `operation.failed` | 单节点执行失败 | 同上 | 该节点 |
| `operation.rejected` | token 失效/确认文本错误/重复提交 | `operation` | 无 |
| `operation.batch` | 批量（>1 节点）执行结束 | `operation` | 无 |

`DetailJson` 字段：`operationId`、`kind`、`title`、`risk`、`nodeName`、`targetId`、`success`、`message`（截断 500 字符）、`taskId`、`durationMs`、`parameterKeys`（**只记键名，不记参数值**，避免泄露密码/密钥）、`handlerDetail`（处理器返回的步骤详情 JSON，截断 500 字符）。批次汇总额外记录 `nodeCount`、`succeeded`、`failed`、`status`。

审计失败不阻断执行结果返回，但记录日志（与登录审计一致）。

## 4. 应用层接口

```csharp
public interface IWriteOperationService
{
    Task<OperationPreview> PreviewAsync(OperationInvocation invocation, ActorInfo actor, CancellationToken ct);
    Task<OperationExecution> ExecuteAsync(Guid tokenId, string? typedConfirmation, ActorInfo actor, CancellationToken ct);
    OperationExecution? GetExecution(Guid operationId);
    IReadOnlyList<OperationExecution> ListRecent(int take);
}
```

- 预览校验：操作类型必须已注册；节点存在、启用、数量在 1..MaxBatchNodes；参数缺失由处理器抛 `OperationValidationException`；
- 执行时重新加载节点（防止预览后节点被删除/禁用）；
- 执行历史保存在内存环形缓冲（默认 200 条），进程重启清空（完整记录在审计表）。

异常类型（Web 层映射为 400/409）：

- `OperationValidationException`（参数/节点不合法，400）
- `OperationConfirmationException`（确认无效/重复，409）
- `OperationNotSupportedException`（Kind 未注册，400）

## 5. Web 接入

### 5.1 HTTP 端点（Admin only，POST 需 CSRF）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/operations/preview` | body `{kind, nodeIds:[guid], parameters:{}}` → `OperationPreview` |
| POST | `/api/operations/{tokenId:guid}/execute` | body `{typedConfirmation}` → `OperationExecution` |
| GET | `/api/operations?take=20` | 最近执行记录 |
| GET | `/api/operations/{id:guid}` | 单次执行详情 |

### 5.2 Blazor 组件（本内核提供，各模块复用）

- `Components/Operations/OperationConfirmDialog.razor`：确认弹窗（目标、警告、风险徽标、确认文本输入、执行按钮）；
- `Components/Operations/RiskBadge.razor`：风险徽标；
- `Components/Operations/OperationResultView.razor`：执行结果（状态、逐节点表格、耗时、错误）；
- 页面组合方式：`PreviewAsync` → 弹窗 → `ExecuteAsync` → `OperationResultView` → 刷新列表。

### 5.3 配置

`appsettings.json`：

```json
"Operations": {
  "ConfirmationTtlSeconds": 120,
  "MaxBatchNodes": 50,
  "NodeLockTimeoutSeconds": 5,
  "ExecuteTimeoutSeconds": 120,
  "DedupeWindowSeconds": 10,
  "HistoryCapacity": 200
}
```

## 8. 已知限制

- 执行历史仅内存，进程重启丢失（审计表保留完整记录）；
- 1Panel 异步任务（如应用安装）若无可轮询接口，结果展示"已提交"并以节点实际状态为准（P5 探测确定）；
- 内核不自动回滚、不自动重试（设计约束）。
