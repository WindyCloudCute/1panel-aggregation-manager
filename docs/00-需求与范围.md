## 1. 背景与目标

1Panel 是开源的 Linux 服务器运维面板，单套面板只管理本机。运维多台服务器时，需要在多个面板之间反复切换、逐个核对资源与网站状态。

PanelFleet 是一个用 .NET 编写的中央控制台，通过 1Panel v2 的 HTTP API（agentless，不在目标机部署额外程序）聚合并管理多台服务器，提供：

1. **统一总览**：所有节点健康状态、资源水位、资源计数一屏可见；
2. **统一清单**：跨节点查看网站、应用、容器、数据库、计划任务，支持过滤与详情；
3. **统一管理**：应用商店安装/卸载/升级、容器/网站/数据库/计划任务管理、系统日志、终端、1Panel 更新；
4. **统一接入管理**：节点 API Key 加密保存、连接测试、能力探测、健康巡检；
5. **统一入口**：OIDC 单点登录、统一审计、写操作二次确认。

> **范围变更（2026-11-16）**：P0 时首版定为“只读聚合”（P0–P4 已按此实现）。现确认扩展为**完整管理控制台**，新增功能按阶段实施，详见 [功能扩展路线图](08-功能扩展路线图.md)。

## 2. 使用角色

| 角色 | 说明 | 权限 |
|---|---|---|
| 运维管理员 | 通过 OIDC 登录的用户；P2–P4 仅单一管理员角色 | 查看/管理全部节点与资源；增删改节点；执行写操作（需二次确认）；查看审计 |
| 只读用户（预留） | `Oidc:ReadOnlyRoles` 命中者 | 仅查看；写操作隐藏/拒绝（后续阶段启用） |

当前不做多角色细粒度授权；审批流不纳入本轮。

## 3. 产品范围（In Scope）

| 模块 | 能力 | 说明 |
|---|---|---|
| 节点管理 | 新增/编辑/删除节点；名称、地址、备注、标签/分组；API Key 与 TLS 策略；连接测试；1Panel 版本与能力探测 | API Key 只写不读，页面仅显示末 4 位提示 |
| 聚合总览 | 每节点：在线状态、CPU/内存/磁盘/负载、系统信息、资源计数；汇总行 | 节点级部分失败降级展示 |
| 资源清单 | 网站、已安装应用、容器、数据库、计划任务；跨节点列表、过滤、排序、详情抽屉 | 每节点取上限 N 条后合并 |
| 应用商店 | 应用搜索/分类/详情；安装（参数表单）、卸载、升级、配置修改；异步任务进度 | 写操作，需二次确认与审计 |
| 容器管理 | 启停/重启/暂停/删除；详情/inspect；日志；资源统计；容器 exec 终端；Compose 管理 | 写操作，需确认与审计 |
| 网站管理 | 启停；基础信息编辑；域名管理；SSL 查看/申请/部署；反向代理配置；网站日志 | 写操作，需确认与审计 |
| 数据库管理 | MySQL/PostgreSQL/MongoDB 实例与库/用户/权限；创建/删除库；密码/描述；备份（接口支持范围内）；Redis 配置与状态 | 写操作，需确认与审计 |
| 计划任务管理 | 增删改；启停；立即执行；分组；执行记录与日志 | 写操作，需确认与审计 |
| 系统日志 | 1Panel 面板日志、系统日志（journal）、容器/网站日志入口；过滤 | 只读 |
| 终端 | 主机 Web 终端 + 容器 exec 终端（WebSocket） | Admin only、会话超时、审计（不记按键内容） |
| 1Panel 更新 | 版本检查/更新说明；单节点与批量升级（强守卫、顺序执行、失败停止） | 高风险，需 Critical 确认 |
| 平台能力 | OIDC 登录/登出；健康检查；操作审计；结构化日志；设置页 | 无本地账号密码登录 |
| 交付 | 单文件发布、Windows 服务、使用文档、安全复核、部署脚本 | P13 |

## 4. 非目标（本轮不做）

- 文件管理器、防火墙、监控告警、备份中心（1Panel 本体功能，后续按需单独立项）；
- 历史监控曲线与告警通知；
- 1Panel v1（`/api/v1`）适配；
- 多租户、多角色细粒度权限、审批流；
- 移动端适配；
- 直接连接 1Panel 数据库或 SSH 到节点（终端通过 1Panel 提供的 WebSocket，不直连 SSH）；
- 替代 1Panel 本体的全部运维能力。

## 5. 关键假设

1. 目标节点均为 **1Panel v2.x**，API 前缀 `/api/v2`；
2. 每个节点已创建并启用 API Key，且 API Key 的 IP 白名单包含本工具出口 IP；
3. 本工具到节点网络可达，支持 HTTP/HTTPS，支持自签证书（按节点配置 TLS 策略）；
4. 存在可用的 OIDC 提供方（Authorization Code + PKCE，confidential client）；
5. 节点规模默认 ≤ 20；更大规模在 P13 压测后调参；
6. 界面语言中文，现代 Chromium 内核浏览器，桌面 1280px 及以上；
7. 写操作遵循“预览 → 二次确认 → 执行 → 审计”，危险操作需输入确认文本；1Panel 升级无自动回滚。

## 6. 验收标准（完整功能）

- 总览在 10 个模拟节点、2 个故障时仍可用；
- 5 类资源清单与详情可用；应用商店可安装/卸载/升级并看到任务进度；
- 容器/网站/数据库/计划任务管理可用，写操作有确认与审计；
- 系统日志与终端可用（终端会话有审计）；
- 1Panel 更新检查与批量升级流程可用且失败停止；
- 所有写操作有审计；API Key 不明文出现；未登录跳 OIDC；
- `dotnet build` 0 warning、`dotnet test` 全绿；
- 交付单文件可执行程序与使用文档。

## 7. 已确认决策（原开放问题）

1. OIDC 提供方：**Pocket ID**，发现地址 `https://auth.example.com/.well-known/openid-configuration`；回调路径 `/sso/OIDC/Callback`（以实际配置为准）。ClientSecret 只通过环境变量注入。
2. 授权模型：**由 Pocket ID 管理可访问用户**；应用默认不维护白名单；`groups` claim 做管理员映射；只读角色预留。
3. 节点规模：默认 20 台设计，并发/缓存可配置。
4. 不使用 Development 假 OIDC；登录验收使用真实 Pocket ID。
5. 项目名称：**PanelFleet**。
6. 代码位置：`D:\文件\子目录`；Git 每次迭代一次提交并打 tag。
7. **范围扩展（2026-11-16）**：完整管理功能分阶段实施（P5–P13），写操作逐次确认 + 审计；终端覆盖主机与容器 exec；1Panel 更新允许单节点和批量升级（强守卫）。
